## Purpose

Позволяет агенту безопасно выполнять разрешённые MCP-инструменты по структурированному запросу модели и использовать фактический результат в итоговом ответе пользователю.

## Requirements

### Requirement: Enabled MCP tools are available to every supported provider
Система SHALL передавать OpenAI, Claude и Ollama актуальные определения автоматически включённых инструментов всех доступных зарегистрированных серверов под квалифицированными именами `server_id__tool_name`. Инструменты из denylist и инструменты недоступных серверов MUST быть скрыты; при наличии хотя бы одного инструмента система SHALL также передавать встроенное определение планирования pipeline. Инструменты MUST NOT передаваться запросам сжатия, суммаризации или проверки инвариантов.

#### Scenario: Tools from several servers are advertised
- **WHEN** два зарегистрированных сервера доступны и объявляют включённые инструменты
- **THEN** основной запрос содержит квалифицированные определения обоих серверов с исходными описаниями, схемами и аннотациями

#### Scenario: Enabled tool is advertised
- **WHEN** доступный сервер объявляет инструмент, отсутствующий в его denylist
- **THEN** основной запрос содержит его квалифицированное имя, описание, схему и аннотации

#### Scenario: Disabled tool is hidden
- **WHEN** нативное имя инструмента присутствует в denylist его сервера
- **THEN** квалифицированное определение не передаётся модели и прямой либо pipeline-вызов запрещён

#### Scenario: Unavailable server is isolated
- **WHEN** один зарегистрированный сервер не подключается, а другой доступен
- **THEN** основной запрос получает инструменты доступного сервера и безопасное предупреждение, но приложение продолжает работу

#### Scenario: Pipeline planner is advertised
- **WHEN** основной запрос получает хотя бы один доступный MCP-инструмент
- **THEN** он также получает встроенное структурированное определение планирования pipeline

#### Scenario: Auxiliary request does not receive tools
- **WHEN** агент выполняет суммаризацию, сжатие контекста или проверку инвариантов
- **THEN** запрос не содержит MCP-инструментов независимо от реестра

#### Scenario: Ollama is the selected provider
- **WHEN** основной запрос выполняется локальной Ollama-моделью и зарегистрированы доступные MCP-инструменты
- **THEN** Ollama получает те же разрешённые квалифицированные определения и встроенный planner, что и облачные провайдеры

### Requirement: Structured tool calls are executed and returned to the model
Система SHALL распознавать нативный структурированный tool call выбранного провайдера, выполнять соответствующий MCP `tools/call` и передавать фактический результат обратно тому же провайдеру для формирования итогового ответа. Текст, лишь похожий на запрос инструмента, MUST NOT запускать MCP-вызов.

#### Scenario: Tool result is used in final answer
- **WHEN** модель возвращает корректный structured tool call разрешённого инструмента, а MCP-сервер успешно его выполняет
- **THEN** система отправляет результат инструмента модели и показывает пользователю сформированный после этого итоговый ответ

#### Scenario: Plain text cannot invoke a tool
- **WHEN** ответ модели содержит имя инструмента или JSON-подобный текст без нативного structured tool call
- **THEN** система рассматривает его как обычный текст и не выполняет MCP-вызов

#### Scenario: Provider can finish without a tool
- **WHEN** модель возвращает итоговый текст без tool call
- **THEN** система завершает обычный цикл ответа без обращения к MCP `tools/call`

#### Scenario: Ollama requests a tool and completes locally
- **WHEN** Ollama возвращает корректный structured tool call и получает фактический результат разрешённого инструмента
- **THEN** продолжение запроса отправляется той же локальной модели, а итоговый текст проходит обычные проверки перед сохранением

### Requirement: Tool execution is constrained and fail-closed
Перед каждым прямым вызовом и шагом pipeline система MUST повторно разрешать квалифицированное имя по снимку активных серверов, `tools/list` и denylist и MUST направлять нативное имя только в найденную сессию. Ошибка маршрута или MCP MUST считаться ошибкой инструмента. Один пользовательский запрос MUST ограничиваться восемью top-level structured tool calls, а один pipeline — восемью последовательными шагами. Модель MUST NOT получать секреты серверов и внешних сервисов.

#### Scenario: Qualified tool is routed
- **WHEN** модель вызывает `github__project_activity`
- **THEN** router отправляет `project_activity` только в сессию сервера `github` и возвращает результат с исходным call ID

#### Scenario: Route is stale or disabled
- **WHEN** сервер, инструмент или разрешение исчезли после формирования определения
- **THEN** система не выполняет вызов на другом сервере и возвращает структурированную ошибку недоступности

#### Scenario: Model requests a disabled tool
- **WHEN** модель вызывает квалифицированный инструмент из denylist либо отсутствующий в свежем discovery
- **THEN** система не выполняет MCP-вызов и возвращает структурированную ошибку недоступности

#### Scenario: Tool call limit is reached
- **WHEN** модель пытается выполнить более восьми top-level structured tool calls
- **THEN** система прекращает цикл до девятого вызова и сообщает о превышении лимита

#### Scenario: Pipeline step limit is reached
- **WHEN** один план содержит более восьми MCP-шагов
- **THEN** система отклоняет план до выполнения первого шага

#### Scenario: MCP call fails
- **WHEN** целевой сервер возвращает ошибку, соединение прерывается или истекает тайм-аут
- **THEN** система не заявляет об успешном действии и передаёт безопасное описание ошибки без секретов

### Requirement: State-changing tool calls require exact user confirmation
Система MUST запросить отдельное интерактивное подтверждение перед каждым tool call, который не объявлен как read-only. Предварительный просмотр SHALL строиться из валидированных аргументов фактического вызова; после подтверждения система MUST выполнить ровно эти аргументы либо запросить новое подтверждение.

#### Scenario: User approves proposed action
- **WHEN** система показывает название операции и её нормализованные аргументы, а пользователь подтверждает действие
- **THEN** система выполняет MCP-вызов с показанными аргументами

#### Scenario: User rejects proposed action
- **WHEN** пользователь отклоняет предварительный просмотр
- **THEN** система не вызывает инструмент, сообщает модели об отмене и формирует итоговый ответ без утверждения об изменении внешней системы

#### Scenario: Model changes arguments after approval
- **WHEN** после подтверждения модель предлагает новый tool call с отличающимися аргументами
- **THEN** система считает его отдельным действием и снова запрашивает подтверждение

### Requirement: Tool activity preserves conversation and invariant guarantees
Технические tool calls и tool results SHALL существовать только в рамках текущего запроса; сохранённая пользовательская история SHALL содержать исходное сообщение и итоговый ответ. Активные инварианты MUST быть проверены против предлагаемого внешнего действия до его подтверждения и выполнения, а итоговый ответ SHALL пройти существующую проверку перед сохранением.

#### Scenario: Proposed action violates an invariant
- **WHEN** структурированный tool call противоречит активному глобальному инварианту
- **THEN** система не предлагает подтверждение, не выполняет инструмент и выдаёт объяснимый отказ с идентификатором правила

#### Scenario: Tool trace is not persisted as dialogue
- **WHEN** запрос с одним или несколькими tool calls успешно завершён
- **THEN** сохранённая история не содержит provider-specific tool call или tool result как обычные сообщения пользователя и ассистента

#### Scenario: Final synthesis fails after a successful write
- **WHEN** внешний инструмент уже успешно изменил состояние, но последующий модельный ответ или его проверка завершается ошибкой
- **THEN** система явно сообщает пользователю о состоявшемся внешнем действии и отдельно о сбое итогового ответа, не пытаясь представить действие как отменённое

### Requirement: Native name collisions are isolated by server ID
Два сервера MAY объявлять одинаковое нативное имя инструмента. Система MUST публиковать и маршрутизировать их как разные квалифицированные имена и MUST отклонять квалифицированное имя, которое невозможно однозначно разобрать.

#### Scenario: Two servers expose search
- **WHEN** серверы `github` и `calendar` объявляют инструмент `search`
- **THEN** модель видит `github__search` и `calendar__search`, а каждый вызов направляется в соответствующий endpoint
