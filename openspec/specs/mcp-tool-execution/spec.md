## Purpose

Позволяет агенту безопасно выполнять разрешённые MCP-инструменты по структурированному запросу модели и использовать фактический результат в итоговом ответе пользователю.

## Requirements

### Requirement: Enabled MCP tools are available to every supported provider
Система SHALL передавать OpenAI и Claude актуальные определения только тех инструментов настроенного MCP-сервера, имена которых присутствуют в сохранённом allowlist. Инструменты SHALL быть доступны только основному модельному запросу и MUST NOT передаваться запросам сжатия, суммаризации или проверки инвариантов.

#### Scenario: Enabled tool is advertised
- **WHEN** настроенный MCP-сервер доступен и объявляет инструмент, имя которого включено пользователем
- **THEN** основной запрос выбранному провайдеру содержит имя, описание и входную схему этого инструмента

#### Scenario: Disabled tool is hidden
- **WHEN** MCP-сервер объявляет инструмент, отсутствующий в сохранённом allowlist
- **THEN** система не передаёт его определение модели и не разрешает его выполнение

#### Scenario: Auxiliary request does not receive tools
- **WHEN** агент выполняет суммаризацию, сжатие контекста или проверку инвариантов
- **THEN** запрос не содержит определений MCP-инструментов независимо от allowlist

### Requirement: Structured tool calls are executed and returned to the model
Система SHALL распознавать нативный структурированный tool call выбранного провайдера, выполнять соответствующий MCP `tools/call` и передавать фактический результат обратно тому же провайдеру для формирования итогового ответа. Текст, лишь похожий на запрос инструмента, MUST NOT запускать MCP-вызов.

#### Scenario: Tool result is used in final answer
- **WHEN** модель возвращает корректный structured tool call разрешённого инструмента, а MCP-сервер успешно его выполняет
- **THEN** система отправляет результат инструмента модели и показывает пользователю сформированный после этого итоговый ответ

#### Scenario: Plain text cannot invoke a tool
- **WHEN** ответ модели содержит имя инструмента или JSON-подобный текст без нативного structured tool call
- **THEN** система рассматривает его как обычный текст и не выполняет MCP-вызов

#### Scenario: Provider can finish without a tool
- **WHEN** модель возвращает итоговый текст без tool call
- **THEN** система завершает обычный цикл ответа без обращения к MCP `tools/call`

### Requirement: Tool execution is constrained and fail-closed
Перед каждым вызовом система MUST повторно проверять имя по снимку актуального списка инструментов и allowlist, MUST ограничивать один пользовательский запрос тремя tool calls и MUST считать ошибку MCP результатом инструмента, а не успешным внешним действием. Модель MUST NOT получать секреты MCP-сервера или CalDAV.

#### Scenario: Model requests a disabled tool
- **WHEN** модель запрашивает отсутствующий, исчезнувший или выключенный инструмент
- **THEN** система не выполняет вызов и возвращает модели структурированную ошибку о недоступности инструмента

#### Scenario: Tool call limit is reached
- **WHEN** модель пытается выполнить более трёх tool calls в рамках одного пользовательского запроса
- **THEN** система прекращает цикл без четвёртого вызова и сообщает пользователю о превышении лимита

#### Scenario: MCP call fails
- **WHEN** разрешённый инструмент возвращает ошибку, соединение прерывается или истекает тайм-аут
- **THEN** система не заявляет об успешном действии и передаёт модели безопасное описание ошибки без учётных данных

### Requirement: State-changing tool calls require exact user confirmation
Система MUST запросить отдельное интерактивное подтверждение перед каждым tool call, который не объявлен как read-only. Предварительный просмотр SHALL строиться из валидированных аргументов фактического вызова; после подтверждения система MUST выполнить ровно эти аргументы либо запросить новое подтверждение.

#### Scenario: User approves proposed action
- **WHEN** система показывает название операции и её нормализованные аргументы, а пользователь подтверждает действие
- **THEN** система выполняет MCP-вызов с показанными аргументами

#### Scenario: User rejects proposed action
- **WHEN** пользователь отклоняет предварительный просмотр
- **THEN** система не вызывает инструмент, сообщает модели об отмене и формирует итоговый ответ без утверждения об изменении внешней системы

#### Scenario: Model changes arguments after approval
- **WHEN** после подтверждения модель предлагает новый tool call с отличающимися аргументами
- **THEN** система считает его отдельным действием и снова запрашивает подтверждение

### Requirement: Tool activity preserves conversation and invariant guarantees
Технические tool calls и tool results SHALL существовать только в рамках текущего запроса; сохранённая пользовательская история SHALL содержать исходное сообщение и итоговый ответ. Активные инварианты MUST быть проверены против предлагаемого внешнего действия до его подтверждения и выполнения, а итоговый ответ SHALL пройти существующую проверку перед сохранением.

#### Scenario: Proposed action violates an invariant
- **WHEN** структурированный tool call противоречит активному глобальному инварианту
- **THEN** система не предлагает подтверждение, не выполняет инструмент и выдаёт объяснимый отказ с идентификатором правила

#### Scenario: Tool trace is not persisted as dialogue
- **WHEN** запрос с одним или несколькими tool calls успешно завершён
- **THEN** сохранённая история не содержит provider-specific tool call или tool result как обычные сообщения пользователя и ассистента

#### Scenario: Final synthesis fails after a successful write
- **WHEN** внешний инструмент уже успешно изменил состояние, но последующий модельный ответ или его проверка завершается ошибкой
- **THEN** система явно сообщает пользователю о состоявшемся внешнем действии и отдельно о сбое итогового ответа, не пытаясь представить действие как отменённое
