# private-llm-service Specification

## Purpose

Определяет наблюдаемое поведение приватного HTTP-сервиса с локальной LLM, выполняющего inference на Raspberry Pi и доступного клиентам только внутри домашней сети.

## Requirements

### Requirement: The model runs on Raspberry Pi
Сервис SHALL выполнять inference модели `qwen3:1.7b` непосредственно на Raspberry Pi 5 и MUST NOT передавать prompt или ответ облачному LLM-провайдеру. Модель SHALL быть настроена с максимальным контекстом 4096 токенов.

#### Scenario: Client sends a generation request
- **WHEN** клиент из разрешённой локальной сети отправляет допустимый запрос модели
- **THEN** Raspberry Pi генерирует ответ установленной локальной моделью без обращения к облачному LLM API

#### Scenario: Context limit is inspected
- **WHEN** оператор выполняет воспроизводимую проверку ограничения контекста
- **THEN** результат проверки подтверждает, что эффективный контекст сервиса не превышает 4096 токенов

### Requirement: Chat is available through a private HTTP API
Сервис SHALL предоставлять HTTP API для одиночных и многошаговых чат-запросов по фиксированному адресу Raspberry Pi. Сетевой gateway SHALL принимать подключения только из настроенной локальной подсети, а backend модели MUST NOT быть доступен клиентам этой подсети напрямую.

#### Scenario: MacBook starts a chat over the network
- **WHEN** MacBook из разрешённой подсети отправляет первое пользовательское сообщение на сетевой endpoint Raspberry Pi
- **THEN** сервис возвращает успешный HTTP-ответ с непустым ответом локальной модели

#### Scenario: Client continues a chat
- **WHEN** клиент отправляет следующую реплику вместе с предыдущими сообщениями диалога
- **THEN** ответ модели учитывает переданную историю чата

#### Scenario: Client bypasses the gateway
- **WHEN** сетевой клиент пытается обратиться к backend-порту модели напрямую
- **THEN** соединение с backend-портом извне Raspberry Pi недоступно

### Requirement: Repeated requests remain stable
Сервис SHALL последовательно обработать установленную проверочную серию из нескольких корректных запросов без аварийного завершения и без необходимости ручного перезапуска между запросами.

#### Scenario: Stability smoke check sends several requests
- **WHEN** проверочный сценарий последовательно отправляет от пяти до десяти корректных запросов
- **THEN** каждый запрос получает завершённый HTTP-ответ, а сервис остаётся доступен для следующего запроса

### Requirement: Request rate is bounded
Сетевой gateway SHALL применять документированный лимит частоты запросов на клиента и SHALL явно отклонять запросы сверх лимита стандартным HTTP-статусом `429`.

#### Scenario: Client exceeds the configured rate
- **WHEN** клиент за контрольный интервал отправляет больше запросов, чем допускает конфигурация gateway
- **THEN** как минимум один запрос сверх лимита получает HTTP `429`, а последующий допустимый запрос может быть обработан без перезапуска сервиса

### Requirement: Verification artifacts are reproducible and privacy-safe
Репозиторий SHALL содержать команды или скрипты для проверки сетевого доступа, чата, серии запросов, rate limit и максимального контекста. Проверочный скрипт SHALL записывать обычный текстовый progress-лог с идентификатором проверки, синтетическим prompt, полным ответом модели, HTTP-статусом, длительностью, результатом pass/fail и безопасной причиной ошибки. Лог и отчёт MUST NOT содержать полный endpoint или реальный IP Raspberry Pi, HTTP-заголовки, credentials либо содержимое пользовательских сессий `fox-llm`.

#### Scenario: Day 30 evidence is prepared
- **WHEN** оператор выполняет документированную процедуру на Raspberry Pi и MacBook
- **THEN** получаются воспроизводимые результаты для каждого обязательного пункта задания и последовательность демонстрации для видео

#### Scenario: Verification log is written
- **WHEN** проверочный скрипт выполняет сценарий с фиксированным синтетическим prompt
- **THEN** текстовый лог содержит секции начала, prompt, полного ответа и завершения со статусом, длительностью и pass/fail без сетевых адресов или credentials
