# mcp-pipeline-execution Specification

## Purpose

Позволяет агенту декларативно составлять ограниченные многошаговые пайплайны из разрешённых MCP-инструментов, безопасно передавать результаты между шагами и получать проверяемую трассировку выполнения.

## Requirements

### Requirement: Agent can propose a structured pipeline
Система SHALL предоставлять основному модельному запросу встроенный структурированный инструмент планирования пайплайна, принимающий имя пайплайна и упорядоченный список шагов. Каждый шаг MUST содержать уникальный идентификатор, имя MCP-инструмента и JSON-объект аргументов; обычный текст или JSON-подобный текст MUST NOT запускать пайплайн.

#### Scenario: Structured plan is accepted for validation
- **WHEN** модель возвращает нативный вызов инструмента планирования с корректно сформированным списком шагов
- **THEN** система разбирает план и передаёт его валидатору до выполнения любого MCP-инструмента

#### Scenario: Plain text cannot start a pipeline
- **WHEN** ответ модели содержит описание пайплайна или JSON-план только как текст
- **THEN** система рассматривает ответ как обычный текст и не выполняет шаги

### Requirement: Pipeline is validated before execution
Система MUST до первого шага проверить, что план содержит от одного до восьми шагов, идентификаторы уникальны, каждый инструмент присутствует в актуальном списке MCP-сервера и allowlist, аргументы являются JSON-объектами, а ссылки `$ref` адресуют только результаты предыдущих шагов. При любой ошибке план MUST быть отклонён целиком без выполнения его шагов.

#### Scenario: Valid linear pipeline passes validation
- **WHEN** каждый шаг использует разрешённый инструмент и ссылается только на доступный результат предыдущего шага
- **THEN** система начинает выполнение шагов в объявленном порядке

#### Scenario: Disabled tool rejects the whole plan
- **WHEN** хотя бы один шаг называет отсутствующий или выключенный MCP-инструмент
- **THEN** система отклоняет план до первого `tools/call` и возвращает безопасную структурированную ошибку

#### Scenario: Forward reference is rejected
- **WHEN** аргумент шага содержит `$ref` на текущий, последующий или неизвестный шаг
- **THEN** система отклоняет план до первого `tools/call`

#### Scenario: Pipeline exceeds the step limit
- **WHEN** модель предлагает более восьми шагов
- **THEN** система отклоняет план и сообщает о допустимом лимите без выполнения MCP-инструментов

### Requirement: Step outputs are resolved into later inputs
Система SHALL после успешного шага сохранять его структурированный результат только в trace текущего запроса и SHALL рекурсивно заменять объект вида `{"$ref":"<step-id>.output"}` в аргументах последующего шага точным JSON-результатом указанного шага. Подставленные аргументы MUST оставаться JSON-объектом и соответствовать входной схеме целевого инструмента.

#### Scenario: Object output is passed without text conversion
- **WHEN** первый шаг возвращает JSON-объект, а последующий шаг ссылается на `<first>.output`
- **THEN** последующий MCP `tools/call` получает этот объект без сериализации в произвольный текст и без потери полей

#### Scenario: Resolved arguments violate the target schema
- **WHEN** после подстановки результата аргументы не соответствуют входной схеме следующего инструмента
- **THEN** следующий инструмент не вызывается, а пайплайн завершается ошибкой этого шага

### Requirement: Pipeline execution is sequential and fail-closed
Система SHALL выполнять шаги строго в объявленном порядке и MUST остановиться после первого результата с ошибкой, тайм-аута, отклонённого подтверждения либо недоступности инструмента. Уже выполненные внешние действия MUST быть отражены в итоговом результате, а невыполненные шаги MUST быть отмечены как skipped; система MUST NOT предпринимать автоматический rollback.

#### Scenario: All steps complete
- **WHEN** каждый шаг успешно выполнен
- **THEN** система возвращает успешный trace со всеми результатами в исходном порядке

#### Scenario: Middle step fails
- **WHEN** промежуточный шаг возвращает ошибку
- **THEN** последующие шаги не вызываются, выполненные шаги сохраняются в trace, а итоговый статус пайплайна является failed

#### Scenario: Failure follows a completed write
- **WHEN** изменяющий состояние шаг уже успешно завершён, а более поздний шаг завершается ошибкой
- **THEN** система явно сообщает о состоявшемся действии и последующей ошибке, не заявляя об откате

### Requirement: Every state-changing step preserves approval and invariants
Система MUST после подстановки ссылок проверить каждый шаг относительно активных глобальных инвариантов и MUST запросить отдельное подтверждение для каждого шага, который не объявлен read-only. Предварительный просмотр SHALL содержать фактическое имя инструмента и нормализованные аргументы, которые будут отправлены в MCP `tools/call`.

#### Scenario: User approves resolved write arguments
- **WHEN** изменяющий шаг прошёл проверку инвариантов и пользователь подтвердил показанные подставленные аргументы
- **THEN** система выполняет ровно этот MCP-вызов и продолжает пайплайн

#### Scenario: User rejects a write step
- **WHEN** пользователь отклоняет изменяющий шаг
- **THEN** инструмент не вызывается, пайплайн останавливается, а последующие шаги отмечаются как skipped

#### Scenario: Resolved step violates an invariant
- **WHEN** фактический MCP-вызов после подстановки противоречит активному глобальному инварианту
- **THEN** система не предлагает подтверждение, не выполняет шаг и завершает пайплайн объяснимым отказом

### Requirement: Arbitrary text reports can be saved to a file
Система SHALL предоставлять изменяющий состояние MCP-инструмент `save_report_to_file`, который принимает безопасное имя одного файла, произвольное UTF-8 содержимое отчёта и необязательный флаг `overwrite`, после подтверждения записывает точное содержимое в текущий рабочий каталог MCP-сервера и возвращает сохранённый путь и число записанных байтов. Инструмент MUST быть независим от предметной области и формата отчёта и MUST отклонять пустое имя, абсолютные пути, `.` или `..`, разделители каталогов и существующие символьные ссылки.

#### Scenario: Arbitrary report is saved
- **WHEN** пользователь подтвердил вызов с безопасным именем нового файла и произвольным UTF-8 содержимым
- **THEN** инструмент записывает точное содержимое в файл текущего рабочего каталога и возвращает путь и число байтов

#### Scenario: Unsafe filename is rejected
- **WHEN** имя пусто, является абсолютным, содержит разделитель каталога, равно `.` или `..` либо указывает на существующую символьную ссылку
- **THEN** инструмент не создаёт и не изменяет файл и возвращает ошибку валидации

#### Scenario: Existing file is protected by default
- **WHEN** целевой обычный файл уже существует, а `overwrite` отсутствует или равен `false`
- **THEN** инструмент не изменяет файл и возвращает ошибку о необходимости явной перезаписи

#### Scenario: Confirmed overwrite replaces an existing file
- **WHEN** целевой обычный файл существует, `overwrite` равен `true` и пользователь подтвердил фактические аргументы вызова
- **THEN** инструмент заменяет содержимое файла точным переданным UTF-8 содержимым

### Requirement: Pipeline trace is isolated from conversation history
Система SHALL возвращать модели структурированный trace с именем пайплайна, общим статусом и статусом каждого шага, но MUST NOT сохранять план, промежуточные результаты или provider-specific сообщения как обычные реплики диалога. Ошибки и trace MUST исключать секреты и иные внутренние данные MCP-сервера.

#### Scenario: Successful trace reaches final synthesis
- **WHEN** пайплайн успешно завершён
- **THEN** модель получает trace как результат встроенного structured tool call и формирует итоговый ответ пользователю

#### Scenario: Persisted history remains user-facing
- **WHEN** запрос выполнил один или несколько шагов пайплайна
- **THEN** сохранённая история содержит исходное сообщение пользователя и итоговый ответ, но не содержит технических шагов и результатов
