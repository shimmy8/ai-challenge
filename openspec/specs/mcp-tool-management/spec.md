# mcp-tool-management Specification

## Purpose

Позволяет пользователю `fox-llm` подключить один MCP-сервер, увидеть объявленные им инструменты и явно выбрать инструменты, разрешённые для будущего использования агентом.

## Requirements

### Requirement: MCP configuration stores named servers
Система SHALL хранить список MCP-серверов, каждый с уникальным стабильным `id`, HTTP(S)-адресом и списком отключённых нативных инструментов. Server ID MUST состоять из безопасных для имени инструмента строчных ASCII-букв, цифр и подчёркиваний и MUST NOT содержать разделитель `__`.

#### Scenario: Several servers survive restart
- **WHEN** пользователь регистрирует несколько проверенных endpoint и перезапускает `fox-llm`
- **THEN** приложение восстанавливает их ID, адреса и denylist независимо друг от друга

#### Scenario: Duplicate server ID is proposed
- **WHEN** пользователь пытается сохранить второй сервер с уже существующим ID
- **THEN** система отклоняет запись и не заменяет существующий сервер неявно

### Requirement: MCP menu manages servers independently
Команда `/mcp` SHALL показывать все зарегистрированные серверы, их адреса, доступность и число доступных и отключённых инструментов. Пользователь SHALL иметь возможность добавить, проверить, изменить и удалить конкретный сервер, не меняя остальные записи.

#### Scenario: One server is unavailable
- **WHEN** `/mcp` проверяет реестр и один endpoint не отвечает
- **THEN** меню показывает ошибку только для этого сервера и продолжает отображать доступные серверы

#### Scenario: Invalid endpoint is proposed
- **WHEN** новый адрес не является HTTP(S) endpoint либо не проходит handshake и `tools/list`
- **THEN** система не сохраняет его и показывает безопасную русскоязычную ошибку

### Requirement: Discovered tools are enabled by default
После успешного `tools/list` система SHALL считать доступным каждый инструмент, имя которого отсутствует в denylist данного сервера. Пользователь SHALL иметь возможность атомарно изменить denylist; новый инструмент сервера MUST становиться доступным автоматически.

#### Scenario: Server adds a new tool
- **WHEN** зарегистрированный сервер начинает объявлять ранее неизвестный инструмент
- **THEN** инструмент доступен агенту при следующем подключении, если пользователь явно его не отключил

#### Scenario: User disables a tool
- **WHEN** пользователь подтверждает отключение обнаруженного инструмента
- **THEN** его нативное имя сохраняется в denylist этого сервера и инструмент не публикуется модели

### Requirement: Local capabilities run as separate named servers
Репозиторий SHALL предоставлять отдельные режимы запуска серверов `github`, `reporting`, `workspace`, `calendar`, `ai`, `telegram` и `orchestrator` на явно заданных loopback-адресах. Серверы MUST объявлять только инструменты своей группы; инструмент `echo` MUST отсутствовать.

#### Scenario: Reporting server is discovered
- **WHEN** клиент подключается к запущенному серверу `reporting`
- **THEN** `tools/list` содержит инструменты расчёта и рендеринга отчёта и не содержит GitHub, календарных, файловых или scheduler-инструментов

#### Scenario: Echo is requested
- **WHEN** клиент ищет или вызывает инструмент `echo` на любом локальном сервере
- **THEN** инструмент отсутствует и вызов не выполняется

### Requirement: Workspace server exposes read-only project inspection
Локальный `workspace` MCP SHALL объявлять read-only инструменты `git_current_branch` и `codegraph_explore`. Оба инструмента SHALL работать относительно фиксированного корня workspace, с которым запущен сервер, и MUST NOT принимать путь к произвольному рабочему каталогу.

#### Scenario: Получение текущей ветки
- **WHEN** клиент вызывает `git_current_branch` в Git-репозитории
- **THEN** инструмент возвращает фактическое имя текущей ветки и не изменяет репозиторий

#### Scenario: Detached HEAD
- **WHEN** клиент вызывает `git_current_branch` при detached HEAD
- **THEN** инструмент возвращает явное состояние detached HEAD без выдуманного имени ветки

#### Scenario: Workspace не является Git-репозиторием
- **WHEN** клиент вызывает `git_current_branch` вне Git-репозитория
- **THEN** инструмент возвращает безопасную диагностическую ошибку без изменения файлов

### Requirement: Интерактивное приложение автоматически предоставляет help-only workspace MCP
При запуске интерактивного режима система SHALL автоматически запускать внутренний loopback MCP для проектной справки на свободном локальном порту. Этот сервер SHALL объявлять только `git_current_branch` и `codegraph_explore`, MUST NOT требовать записи в пользовательский MCP registry и MUST NOT предоставлять `save_report` либо инструменты других серверных групп.

#### Scenario: Автоматический запуск проектных инструментов
- **WHEN** пользователь запускает интерактивный `fox-llm`
- **THEN** система делает `git_current_branch` и `codegraph_explore` доступными help-субагенту без отдельного процесса, фиксированного порта и ручной регистрации через `/mcp`

#### Scenario: Изоляция набора инструментов
- **WHEN** help-субагент получает список инструментов внутреннего MCP
- **THEN** список содержит только `git_current_branch` и `codegraph_explore` с read-only аннотациями и не содержит `save_report` или пользовательские MCP tools

#### Scenario: Завершение приложения
- **WHEN** интерактивное приложение завершает работу
- **THEN** система закрывает внутреннее MCP-соединение, ограничивает graceful shutdown бюджетом 200 мс, после тайм-аута отменяет loopback server и не оставляет фоновую задачу или запись конфигурации

#### Scenario: Внутренний MCP недоступен
- **WHEN** внутренний help-only MCP невозможно запустить или подключить
- **THEN** обычный интерактивный клиент продолжает работу, а project help явно сообщает об ограничении MCP-контекста

### Requirement: CodeGraph analysis is constrained to the workspace
Инструмент `codegraph_explore` SHALL принимать непустой текстовый вопрос, запускать CodeGraph без shell-интерпретации относительно фиксированного workspace и возвращать ограниченный текстовый результат. Инструмент MUST проверять наличие `.codegraph/`, применять тайм-аут и предел вывода и MUST NOT читать либо раскрывать локальные файлы секретов.

#### Scenario: Успешный анализ кода
- **WHEN** workspace содержит `.codegraph/`, бинарник CodeGraph доступен и клиент передаёт допустимый вопрос
- **THEN** инструмент запускает анализ относительно workspace и возвращает ограниченный результат как read-only данные

#### Scenario: Индекс CodeGraph отсутствует
- **WHEN** в workspace отсутствует `.codegraph/`
- **THEN** инструмент завершается безопасной ошибкой доступности и не пытается индексировать проект автоматически

#### Scenario: Бинарник CodeGraph отсутствует
- **WHEN** процесс CodeGraph невозможно запустить
- **THEN** инструмент возвращает безопасную диагностическую ошибку без shell fallback

#### Scenario: Недопустимый вопрос
- **WHEN** вопрос пуст, превышает разрешённую длину или содержит только пробельные символы
- **THEN** инструмент отклоняет вызов до запуска дочернего процесса

#### Scenario: Тайм-аут или чрезмерный вывод
- **WHEN** CodeGraph не завершается в срок либо создаёт вывод сверх установленного предела
- **THEN** инструмент прекращает обработку, не оставляет дочерний процесс в фоне и возвращает безопасную ограниченную ошибку
