# telegram-digest-delivery Specification

## Purpose
Обеспечивает автономное формирование календарной сводки через выбранного LLM-провайдера и безопасную доставку результата в один заранее настроенный Telegram-чат.

## Requirements

### Requirement: Background digest uses isolated model context
Для каждого запуска система SHALL формировать ограниченный запрос настроенному OpenAI или Claude только из фиксированных инструкций, абсолютного интервала и нормализованных календарных событий. Фоновый запрос MUST NOT получать историю интерактивного диалога, долговременную память, MCP-инструменты или право выполнять внешние действия.

#### Scenario: Digest is generated successfully
- **WHEN** календарные данные собраны и настроенный LLM-провайдер отвечает успешно
- **THEN** система сохраняет сформированный текст сводки и передаёт ровно этот текст компоненту доставки

#### Scenario: Interactive conversation contains private context
- **WHEN** в сохранённых сессиях есть сообщения или факты, не относящиеся к календарному запуску
- **THEN** они не включаются в фоновый запрос и не могут появиться в доставленной сводке

#### Scenario: Model returns a tool call
- **WHEN** LLM-провайдер неожиданно возвращает запрос инструмента вместо текста
- **THEN** система не выполняет инструмент и использует резервную детерминированную сводку

### Requirement: A deterministic digest is always available after collection
После успешного чтения календаря система SHALL построить детерминированный текст из количества и упорядоченного списка событий до обращения к LLM. Если событий нет, текст SHALL явно сообщать об отсутствии событий за интервал. Ошибка LLM, отсутствие ключа или непригодный ответ MUST NOT отменять доставку детерминированной сводки.

#### Scenario: Provider is unavailable
- **WHEN** календарь прочитан, но запрос к OpenAI или Claude завершается ошибкой
- **THEN** система отмечает использование fallback, сохраняет безопасное описание ошибки и отправляет детерминированную сводку

#### Scenario: Calendar interval is empty
- **WHEN** за выбранный интервал нет событий
- **THEN** система отправляет понятное сообщение об отсутствии событий, а не пустой текст

### Requirement: Telegram destination is fixed by local configuration
Система SHALL отправлять сводки только в Telegram-чат, заранее заданный локальными настройками MCP-сервера. Bot token и chat ID MUST NOT приниматься как аргументы MCP-инструментов, сохраняться в заданиях или результатах, передаваться LLM, возвращаться клиенту либо появляться в логах и ошибках.

#### Scenario: Telegram is configured
- **WHEN** bot token и chat ID доступны локальному MCP-серверу
- **THEN** компонент доставки может отправить сводку в единственный настроенный чат без раскрытия реквизитов

#### Scenario: Telegram configuration is missing
- **WHEN** наступает запуск, но обязательная настройка Telegram отсутствует
- **THEN** система не выполняет сетевую отправку, сохраняет безопасную ошибку конфигурации и не выводит частично заданные значения

#### Scenario: Model proposes another recipient
- **WHEN** вывод модели содержит chat ID, имя пользователя или URL другого получателя
- **THEN** система рассматривает это как обычный текст и всё равно использует только локально настроенный Telegram-чат

### Requirement: Delivery outcome is recorded without false success
Каждая попытка SHALL сохранять отправленный текст, используемый источник текста (`llm` или `fallback`), время и один из результатов `delivered`, `failed` или `unknown`. Успешный ответ Telegram SHALL фиксироваться как `delivered`; однозначный отказ SHALL быть `failed`; потеря соединения после отправки, при которой принятие сообщения нельзя установить, SHALL быть `unknown` и MUST NOT автоматически повторяться.

#### Scenario: Telegram accepts the message
- **WHEN** Telegram подтверждает успешную отправку
- **THEN** запуск сохраняется как доставленный вместе с безопасным идентификатором сообщения

#### Scenario: Telegram rejects the message
- **WHEN** Telegram возвращает однозначную ошибку до успешного принятия
- **THEN** запуск сохраняется как неуспешный с безопасным описанием причины

#### Scenario: Delivery outcome is uncertain
- **WHEN** соединение прерывается после отправки запроса и ответ Telegram неизвестен
- **THEN** запуск сохраняется как `unknown`, автоматически не повторяется и доступен в истории для ручной проверки или повторного запуска

### Requirement: Calendar source failures do not produce invented digests
Если календарные события не удалось получить, система MUST NOT просить LLM сочинить сводку и MUST NOT отправлять текст, представляющий календарь успешно прочитанным. Запуск SHALL завершиться ошибкой сбора данных, доступной в агрегированной истории.

#### Scenario: CalDAV request fails
- **WHEN** календарный сервер недоступен или отклоняет чтение
- **THEN** система не вызывает генератор сводки, не отправляет Telegram-сообщение и сохраняет безопасную ошибку запуска
