## Purpose

Предоставляет MCP-инструмент для подтверждаемого создания личных событий в Яндекс Календаре через CalDAV без передачи основного пароля аккаунта агенту.

## Requirements

### Requirement: Calendar tool declares a complete input contract
Локальный MCP-сервер SHALL регистрировать инструмент `create_calendar_event` с описанием и JSON Schema, в которой `title`, `start_at` и `end_at` обязательны, а `description` и `location` необязательны. Начало и окончание MUST быть абсолютными значениями даты и времени с часовым смещением.

#### Scenario: Tool appears in discovery
- **WHEN** клиент выполняет MCP handshake и `tools/list` локального сервера
- **THEN** список содержит `create_calendar_event`, его описание, признаки изменяющей состояние операции и входную схему

#### Scenario: Required argument is absent
- **WHEN** инструмент вызван без названия, начала или окончания
- **THEN** сервер отклоняет вызов до обращения к Яндекс Календарю и возвращает понятную ошибку валидации

#### Scenario: Time range is invalid
- **WHEN** окончание события не позже его начала либо значение времени не содержит смещения
- **THEN** сервер не создаёт событие и возвращает понятную ошибку валидации

### Requirement: Ambiguous natural-language requests are clarified
Агент SHALL использовать текущую дату и `Europe/Moscow` для преобразования относительных дат в абсолютные значения. Если пользователь не указал время начала или длительность встречи, агент MUST запросить недостающие сведения и MUST NOT подставлять скрытые значения по умолчанию либо вызывать календарный инструмент.

#### Scenario: Complete relative request is normalized
- **WHEN** пользователь просит создать встречу «завтра в 15:00 на час»
- **THEN** предварительный просмотр показывает соответствующие абсолютные начало и окончание следующего календарного дня в `Europe/Moscow`

#### Scenario: Time is missing
- **WHEN** пользователь просит создать встречу «завтра», не указывая время
- **THEN** агент уточняет время и не предлагает подтверждение создания события

#### Scenario: Duration is missing
- **WHEN** пользователь указал начало, но не указал окончание или длительность
- **THEN** агент уточняет длительность и не предлагает подтверждение создания события

### Requirement: Personal Yandex Calendar credentials stay local
MCP-сервер SHALL авторизоваться в личном Яндекс Календаре по CalDAV с логином и отдельным паролем приложения из переменных окружения. Система MUST NOT принимать или сохранять основной пароль Яндекс ID и MUST NOT включать логин, пароль приложения или заголовок авторизации в tool result, историю, метрики или пользовательские ошибки.

#### Scenario: App password credentials are configured
- **WHEN** заданы необходимые переменные окружения и пароль приложения действителен
- **THEN** сервер может обнаружить доступные пользователю календари и выполнить подтверждённое создание события

#### Scenario: Credentials are absent or rejected
- **WHEN** переменные окружения отсутствуют либо Яндекс отклоняет авторизацию
- **THEN** инструмент не создаёт событие и возвращает безопасную инструкцию проверить CalDAV-логин и пароль приложения без вывода их значений

### Requirement: Calendar target is selected without guessing
Сервер SHALL обнаруживать доступные для записи CalDAV-календари. Если доступен ровно один календарь, он SHALL использоваться автоматически; если их несколько, сервер MUST требовать явного выбора по настроенному имени и MUST NOT произвольно выбирать первый календарь.

#### Scenario: One writable calendar exists
- **WHEN** CalDAV discovery возвращает ровно один доступный для записи календарь
- **THEN** подтверждённое событие создаётся в этом календаре без дополнительной настройки

#### Scenario: Several writable calendars exist without selection
- **WHEN** discovery возвращает несколько доступных для записи календарей, а имя целевого календаря не настроено
- **THEN** инструмент не создаёт событие и возвращает список доступных названий с инструкцией выбрать одно

#### Scenario: Configured calendar is found
- **WHEN** имя целевого календаря настроено и однозначно совпадает с доступным для записи календарём
- **THEN** подтверждённое событие создаётся в выбранном календаре

### Requirement: Confirmed event is created once and reported accurately
После подтверждения MCP-сервер SHALL создать одно CalDAV-событие с уникальным идентификатором и переданными названием, началом, окончанием, описанием и местом. Успешный результат SHALL содержать безопасные данные созданного события и его идентификатор; повтор транспортного запроса с тем же идентификатором MUST NOT создавать дубликат.

#### Scenario: Confirmed creation succeeds
- **WHEN** пользователь подтвердил валидный вызов и CalDAV-сервер принял событие
- **THEN** в выбранном Яндекс Календаре появляется одно событие с подтверждёнными полями, а агент сообщает о фактическом успехе

#### Scenario: User cancels creation
- **WHEN** пользователь отклоняет предварительный просмотр календарного события
- **THEN** CalDAV-запрос на запись не отправляется и календарь остаётся без изменений

#### Scenario: Network outcome is uncertain
- **WHEN** соединение обрывается после отправки записи и клиент не может однозначно определить результат
- **THEN** система не повторяет создание с новым идентификатором, сообщает о неопределённом результате и предлагает проверить календарь
