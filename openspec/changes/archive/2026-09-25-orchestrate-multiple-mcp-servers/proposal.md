## Why

Текущий MCP-клиент подключает только один сервер, а локальный MCP-сервер смешивает GitHub, отчёты, файловую систему, календарь, scheduler и Telegram в одном процессе. Периодические задания дополнительно зашиты под календарную сводку, поэтому существующий pipeline нельзя повторно использовать для произвольных источников, преобразований и выходов.

## What Changes

- **BREAKING**: заменить одиночный MCP endpoint реестром именованных серверов без миграции прежнего формата конфигурации.
- Автоматически включать все обнаруженные инструменты и хранить только явный список отключённых инструментов для каждого сервера.
- Публиковать инструменты модели под квалифицированными именами `server_id__tool_name` и маршрутизировать каждый вызов в соответствующую MCP-сессию.
- **BREAKING**: удалить демонстрационный инструмент `echo` и разделить локальный монолит на серверы `github`, `reporting`, `workspace`, `calendar`, `ai`, `telegram` и `orchestrator`.
- Вынести выполнение линейного pipeline в общий исполнитель, используемый интерактивным агентом и фоновыми заданиями.
- **BREAKING**: заменить календарно-специфичные задания универсальными сохраняемыми заданиями, которые по расписанию выполняют подтверждённый pipeline из MCP-инструментов.
- Добавить изолированный AI-инструмент для текстового преобразования без истории, памяти и tool calling.
- Сделать чтение календарных событий публичным read-only MCP-инструментом и Telegram-доставку — отдельным изменяющим состояние инструментом с локально фиксированным получателем.
- Сохранять трассировку каждого фонового запуска и печатать безопасные логи MCP-вызовов в stdout с сервером, инструментом, шагом, статусом и длительностью.
- Добавить сквозной сценарий GitHub → reporting → workspace и периодический сценарий calendar → AI → Telegram, проверяющие выбор инструментов, серверную маршрутизацию и порядок вызовов.

## Capabilities

### New Capabilities

- `scheduled-pipeline-jobs`: Универсальные сохраняемые задания, которые выполняют подтверждённый межсерверный MCP-pipeline по расписанию.
- `isolated-ai-processing`: Изолированное текстовое преобразование через отдельный MCP-сервер без доступа к диалогу, памяти и инструментам.
- `telegram-message-delivery`: Отдельный MCP-инструмент доставки текста в единственный локально настроенный Telegram-чат.
- `mcp-call-observability`: Безопасные коррелируемые stdout-логи серверного выполнения MCP-вызовов без диагностического шума в интерактивной выдаче агента.

### Modified Capabilities

- `mcp-tool-management`: Реестр нескольких именованных серверов, denylist инструментов и отдельные режимы запуска локальных серверов вместо одного сервера и allowlist.
- `mcp-tool-execution`: Квалифицированные имена, маршрутизация между сессиями, частичная доступность серверов и выполнение инструментов разных серверов.
- `mcp-pipeline-execution`: Межсерверные pipeline, общий исполнитель, runtime-ссылки и предварительное разрешение фонового pipeline.
- `scheduled-background-jobs`: Универсальные периодические MCP-pipeline вместо календарно-специфичной модели задания и runner.
- `yandex-calendar-events`: Публичный read-only инструмент чтения событий для использования как источника pipeline.
- `telegram-digest-delivery`: Отдельный Telegram MCP-сервер с фиксированным локальным получателем, пригодный как выход подтверждённого фонового pipeline.
- `github-project-reporting`: Распределение GitHub, вычислительных и файловых инструментов между серверами и проверяемый трёхсерверный flow.

## Impact

- Изменятся `src/config.rs`, `src/app.rs`, `src/agent.rs`, `src/cli.rs` и provider-neutral MCP-типы.
- Код серверов, scheduler, background runner, Calendar, GitHub, reporting и Telegram останется внутри `src/mcp/`, но будет разделён по отдельным server handler и общему executor.
- Формат `.fox-llm.json`, CLI `/mcp`, аргументы `--mcp-server`, имена публичных инструментов и SQLite-схема scheduler изменятся без legacy-миграции.
- Понадобятся изолированные тестовые MCP-серверы, временная SQLite-база и сквозные тесты маршрутизации, порядка, отказов, подтверждений и безопасного логирования.
- Локальные секреты CalDAV, Telegram, GitHub и LLM останутся вне tool arguments, результатов, истории и stdout.
