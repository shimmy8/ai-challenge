## MODIFIED Requirements

### Requirement: Pipeline is validated before execution
Система MUST до первого шага проверить, что план содержит от одного до восьми шагов, идентификаторы уникальны, каждое квалифицированное имя разрешается в доступный и не отключённый инструмент конкретного сервера, аргументы являются JSON-объектами, а ссылки адресуют только runtime-контекст либо результаты предыдущих шагов. При любой ошибке интерактивный план MUST быть отклонён целиком; сохранённый фоновый запуск MUST завершиться failed без выполнения первого шага.

#### Scenario: Valid linear pipeline passes validation
- **WHEN** каждый шаг использует доступный квалифицированный инструмент и ссылается только на runtime либо предыдущие результаты
- **THEN** система начинает выполнение шагов в объявленном порядке и на указанных серверах

#### Scenario: Disabled tool rejects the whole plan
- **WHEN** хотя бы один шаг называет отсутствующий или отключённый инструмент
- **THEN** система не выполняет ни одного `tools/call` и возвращает безопасную структурированную ошибку

#### Scenario: Forward reference is rejected
- **WHEN** аргумент шага содержит ссылку на текущий, последующий или неизвестный шаг
- **THEN** система отклоняет план до первого MCP-вызова

#### Scenario: Pipeline exceeds the step limit
- **WHEN** план содержит более восьми шагов
- **THEN** система отклоняет его без выполнения инструментов

### Requirement: Step outputs are resolved into later inputs
Система SHALL после успешного шага сохранять его структурированный результат в trace запуска и SHALL рекурсивно заменять ссылку на `<step-id>.output` точным JSON-результатом либо ссылку на вложенное поле соответствующим JSON-значением. В фоновом режиме система SHALL также разрешать объявленные поля `run`. Подставленные аргументы MUST оставаться JSON-объектом и соответствовать входной схеме целевого инструмента.

#### Scenario: Object output is passed without text conversion
- **WHEN** последующий шаг ссылается на полный output предыдущего шага
- **THEN** целевой MCP-вызов получает исходное JSON-значение без текстовой сериализации и потери полей

#### Scenario: Nested output field is selected
- **WHEN** аргумент ссылается на существующее вложенное поле предыдущего результата
- **THEN** система подставляет значение этого поля, сохраняя его JSON-тип

#### Scenario: Resolved arguments violate the target schema
- **WHEN** после подстановки аргументы не соответствуют входной схеме
- **THEN** целевой инструмент не вызывается, а pipeline завершается ошибкой этого шага

### Requirement: Every state-changing step preserves approval and invariants
В интерактивном режиме система MUST после подстановки ссылок проверить каждый шаг относительно глобальных инвариантов и запросить отдельное подтверждение для каждого не read-only инструмента. Для сохранённого фонового задания система MUST выполнить только заранее показанную и подтверждённую неизменяемую структуру pipeline; изменение структуры MUST требовать нового подтверждения до следующего запуска.

#### Scenario: User approves resolved write arguments
- **WHEN** изменяющий шаг интерактивного pipeline прошёл проверку и пользователь подтвердил фактические аргументы
- **THEN** система выполняет ровно показанный MCP-вызов

#### Scenario: Scheduled write was pre-authorized
- **WHEN** наступает запуск сохранённого задания с подтверждённым write-step и неизменившейся структурой
- **THEN** шаг выполняется без недоступного в фоне интерактивного prompt

#### Scenario: User rejects a write step
- **WHEN** пользователь отклоняет изменяющий шаг
- **THEN** инструмент не вызывается, pipeline останавливается, а последующие шаги отмечаются skipped

#### Scenario: Resolved step violates an invariant
- **WHEN** фактический вызов после подстановки ссылок противоречит активному глобальному инварианту
- **THEN** система не предлагает подтверждение, не вызывает инструмент и завершает pipeline объяснимым отказом

### Requirement: Arbitrary text reports can be saved to a file
Сервер `workspace` SHALL предоставлять изменяющий состояние инструмент `save_report`, который принимает безопасное имя одного файла, произвольное UTF-8 содержимое и необязательный `overwrite`, записывает точное содержимое только в настроенный рабочий каталог и возвращает путь и число байтов. Инструмент MUST отклонять пустое имя, абсолютные пути, `.` или `..`, разделители каталогов и существующие символические ссылки.

#### Scenario: Arbitrary report is saved
- **WHEN** авторизованный вызов содержит безопасное имя нового файла и UTF-8 содержимое
- **THEN** `workspace__save_report` записывает точное содержимое и возвращает путь и число байтов

#### Scenario: Unsafe filename is rejected
- **WHEN** имя небезопасно либо указывает на символическую ссылку
- **THEN** инструмент не создаёт и не изменяет файл

#### Scenario: Existing file is protected by default
- **WHEN** файл существует, а `overwrite` отсутствует или равен false
- **THEN** инструмент не изменяет файл и возвращает ошибку о необходимости явной перезаписи

#### Scenario: Confirmed overwrite replaces an existing file
- **WHEN** файл существует, `overwrite=true` и вызов авторизован выбранной политикой выполнения
- **THEN** инструмент заменяет содержимое точным переданным UTF-8 текстом

## ADDED Requirements

### Requirement: Interactive and scheduled flows share execution semantics
Интерактивный агент и orchestrator SHALL использовать один контракт валидации, разрешения ссылок, последовательного выполнения, тайм-аутов, fail-closed остановки и формирования trace. Различаться MAY только источник runtime-контекста и политика подтверждения внешних действий.

#### Scenario: The same tool step fails in both modes
- **WHEN** одинаковый шаг получает одинаковую MCP-ошибку в интерактивном и фоновом pipeline
- **THEN** оба режима останавливают последующие шаги и формируют эквивалентные статусы failed и skipped

### Requirement: Trace identifies every server route
Trace каждого шага SHALL содержать квалифицированное имя, server ID, нативное имя инструмента, порядковый номер, статус и безопасную длительность. Trace MUST сохранять исходный порядок даже при ошибке и MUST NOT включать секреты.

#### Scenario: Three-server report completes
- **WHEN** pipeline вызывает GitHub, reporting и workspace серверы
- **THEN** trace однозначно показывает правильный сервер и порядок каждого шага
