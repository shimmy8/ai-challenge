## MODIFIED Requirements

### Requirement: Enabled MCP tools are available to every supported provider
Система SHALL передавать OpenAI и Claude актуальные определения автоматически включённых инструментов всех доступных зарегистрированных серверов под квалифицированными именами `server_id__tool_name`. Инструменты из denylist и инструменты недоступных серверов MUST быть скрыты; при наличии хотя бы одного инструмента система SHALL также передавать встроенное определение планирования pipeline. Инструменты MUST NOT передаваться запросам сжатия, суммаризации или проверки инвариантов.

#### Scenario: Tools from several servers are advertised
- **WHEN** два зарегистрированных сервера доступны и объявляют включённые инструменты
- **THEN** основной запрос содержит квалифицированные определения обоих серверов с исходными описаниями, схемами и аннотациями

#### Scenario: Enabled tool is advertised
- **WHEN** доступный сервер объявляет инструмент, отсутствующий в его denylist
- **THEN** основной запрос содержит его квалифицированное имя, описание, схему и аннотации

#### Scenario: Disabled tool is hidden
- **WHEN** нативное имя инструмента присутствует в denylist его сервера
- **THEN** квалифицированное определение не передаётся модели и прямой либо pipeline-вызов запрещён

#### Scenario: Unavailable server is isolated
- **WHEN** один зарегистрированный сервер не подключается, а другой доступен
- **THEN** основной запрос получает инструменты доступного сервера и безопасное предупреждение, но приложение продолжает работу

#### Scenario: Pipeline planner is advertised
- **WHEN** основной запрос получает хотя бы один доступный MCP-инструмент
- **THEN** он также получает встроенное структурированное определение планирования pipeline

#### Scenario: Auxiliary request does not receive tools
- **WHEN** агент выполняет суммаризацию, сжатие контекста или проверку инвариантов
- **THEN** запрос не содержит MCP-инструментов независимо от реестра

### Requirement: Tool execution is constrained and fail-closed
Перед каждым прямым вызовом и шагом pipeline система MUST повторно разрешать квалифицированное имя по снимку активных серверов, `tools/list` и denylist и MUST направлять нативное имя только в найденную сессию. Ошибка маршрута или MCP MUST считаться ошибкой инструмента. Один пользовательский запрос MUST ограничиваться восемью top-level structured tool calls, а один pipeline — восемью последовательными шагами. Модель MUST NOT получать секреты серверов и внешних сервисов.

#### Scenario: Qualified tool is routed
- **WHEN** модель вызывает `github__project_activity`
- **THEN** router отправляет `project_activity` только в сессию сервера `github` и возвращает результат с исходным call ID

#### Scenario: Route is stale or disabled
- **WHEN** сервер, инструмент или разрешение исчезли после формирования определения
- **THEN** система не выполняет вызов на другом сервере и возвращает структурированную ошибку недоступности

#### Scenario: Model requests a disabled tool
- **WHEN** модель вызывает квалифицированный инструмент из denylist либо отсутствующий в свежем discovery
- **THEN** система не выполняет MCP-вызов и возвращает структурированную ошибку недоступности

#### Scenario: Tool call limit is reached
- **WHEN** модель пытается выполнить более восьми top-level structured tool calls
- **THEN** система прекращает цикл до девятого вызова и сообщает о превышении лимита

#### Scenario: Pipeline step limit is reached
- **WHEN** один план содержит более восьми MCP-шагов
- **THEN** система отклоняет план до выполнения первого шага

#### Scenario: MCP call fails
- **WHEN** целевой сервер возвращает ошибку, соединение прерывается или истекает тайм-аут
- **THEN** система не заявляет об успешном действии и передаёт безопасное описание ошибки без секретов

## ADDED Requirements

### Requirement: Native name collisions are isolated by server ID
Два сервера MAY объявлять одинаковое нативное имя инструмента. Система MUST публиковать и маршрутизировать их как разные квалифицированные имена и MUST отклонять квалифицированное имя, которое невозможно однозначно разобрать.

#### Scenario: Two servers expose search
- **WHEN** серверы `github` и `calendar` объявляют инструмент `search`
- **THEN** модель видит `github__search` и `calendar__search`, а каждый вызов направляется в соответствующий endpoint
