## Purpose

Делает выполнение MCP-вызовов наблюдаемым через безопасные stdout-логи отдельных серверных процессов, не засоряя интерактивную выдачу агента.

## ADDED Requirements

### Requirement: Every server MCP call emits correlated lifecycle logs
Каждый целевой локальный MCP-сервер SHALL печатать в stdout своего отдельного процесса однострочные записи начала и завершения вызова. Записи MUST включать correlation ID, server ID, нативное имя инструмента, идентификатор шага при наличии, статус и длительность завершённого вызова. Интерактивный клиент SHALL NOT дублировать эти диагностические записи в пользовательской выдаче агента.

#### Scenario: Cross-server pipeline succeeds
- **WHEN** pipeline последовательно вызывает инструменты нескольких серверов
- **THEN** stdout серверных процессов позволяет восстановить сервер, инструмент, порядок и итог каждого вызова по correlation ID, а выдача интерактивного агента не содержит диагностических JSONL-записей

#### Scenario: Tool call fails
- **WHEN** сервер возвращает ошибку или клиентский тайм-аут истекает
- **THEN** завершающая запись содержит статус ошибки и длительность без ложного сообщения об успехе

### Requirement: Logs exclude payloads and credentials by default
Логи MCP-вызовов MUST NOT содержать полные аргументы, результаты, authorization headers, API keys, CalDAV credentials, Telegram token или chat ID. Безопасные идентификаторы сервера, инструмента, job, run и step MAY выводиться для корреляции.

#### Scenario: Sensitive tool is called
- **WHEN** вызов использует локальные реквизиты либо обрабатывает пользовательский текст
- **THEN** stdout содержит только безопасные метаданные вызова и не содержит payload или секреты
