## ADDED Requirements

### Requirement: Индексатор поддерживает изолированный review-профиль корпуса
Система SHALL предоставлять явно выбираемый review-профиль discovery, который включает разрешённую проектную документацию и поддерживаемые текстовые файлы исходного кода из указанной доверенной базовой директории. Профиль SHALL детерминированно исключать `.git`, `target`, vendor/generated-каталоги, бинарные файлы, локальные базы, env-файлы, credential-конфигурации и пути вне выбранного корня. Существующее поведение команды `index` без review-профиля SHALL оставаться Markdown-only и обратно совместимым.

#### Scenario: Review-профиль индексирует документацию и Rust-код
- **WHEN** review-профиль получает базовую директорию с Markdown-документами и файлами `.rs`
- **THEN** оба типа источников обнаруживаются в детерминированном порядке и получают относительный provenance внутри выбранного корня

#### Scenario: Чувствительные и generated-файлы исключаются
- **WHEN** базовая директория содержит `.env-mcp`, `.fox-embeddings.json`, SQLite-базы, `target/`, vendor/generated-каталоги или бинарные файлы
- **THEN** review-профиль не читает и не добавляет их содержимое в документы, чанки, embeddings, логи или ошибки

#### Scenario: Путь выходит за пределы корня
- **WHEN** symlink, относительный путь или иной кандидат разрешается за пределами выбранной базовой директории
- **THEN** индексатор отклоняет кандидат до чтения его содержимого и продолжает безопасную обработку остальных источников

#### Scenario: Обычная индексация не изменилась
- **WHEN** пользователь запускает существующую команду `fox-llm index` без review-профиля
- **THEN** discovery по-прежнему индексирует только прежний Markdown-корпус и не добавляет исходный код автоматически

### Requirement: Исходный код получает пригодные для retrieval метаданные
Для текстового исходного кода review-профиль SHALL формировать стабильные чанки с относительным `source`, именем файла как `title`, языком и ближайшим доступным структурным контекстом как `section`. Если структурный разбор языка недоступен, система SHALL применять Unicode-safe fixed chunking с overlap и MUST NOT объявлять выведенные имена символов достоверными.

#### Scenario: Поддерживаемый исходный файл разбит структурно
- **WHEN** индексатор умеет достоверно определить границы структурных элементов исходного файла
- **THEN** чанки сохраняют соответствующий структурный контекст и стабильный provenance

#### Scenario: Структурный разбор недоступен
- **WHEN** текстовое расширение разрешено, но специализированный parser для языка отсутствует
- **THEN** файл индексируется безопасным fixed chunking, а section обозначает файл или диапазон строк без выдуманного имени символа
