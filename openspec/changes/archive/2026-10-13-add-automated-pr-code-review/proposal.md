## Why

Новые pull request сейчас требуют полностью ручного просмотра, хотя `fox-llm` уже умеет обращаться к LLM, строить RAG-индекс и читать данные GitHub. Нужен воспроизводимый и безопасный CI-процесс, который автоматически сопоставляет diff с документацией и соседним кодом и публикует полезное первичное ревью прямо в PR.

## What Changes

- Добавить неинтерактивный режим `review-pr`, который получает metadata, список файлов и patch pull request через GitHub API, не исполняя код PR.
- Добавить review-ориентированный RAG-корпус из документации и разрешённых текстовых файлов исходного кода базовой ветки.
- Формировать структурированное ревью с потенциальными багами, архитектурными проблемами, рекомендациями, severity и проверяемой привязкой к файлам и строкам diff.
- Ограничивать число файлов и объём diff, пакетировать большие входы и явно отмечать частичный анализ без падения pipeline.
- Добавить предварительный test job без secrets, который исполняет код PR, запускает `cargo test` и передаёт статус с ограниченным очищенным логом следующему job как недоверенные данные.
- Добавить GitHub Actions review job, который всегда запускается после test job, использует доверенную реализацию из base-ветки, читает настройки из Actions variables/secrets и создаёт либо обновляет один Markdown-комментарий в PR вместе с кратким Actions Summary.
- При успешных тестах публиковать обычное AI-review, а при падении дополнительно объяснять подтверждённую, вероятную либо не установленную причину в разделе `Почему упали тесты`, не смешивая test failure с инфраструктурной ошибкой.
- Пропускать fork PR без передачи credentials; не публиковать секреты, полные конфигурации или чувствительное содержимое в логах и результатах.

## Capabilities

### New Capabilities

- `automated-pr-code-review`: безопасный запуск тестов и AI-review для pull request, получение diff и ограниченного test report, RAG по документации и коду, структурированный результат и публикация sticky-комментария.

### Modified Capabilities

- `document-indexing`: добавить явно выбираемый профиль корпуса для исходного кода и документации, не изменяя существующий Markdown-корпус команды `index` по умолчанию.

## Impact

- Затрагиваются `app.rs`, новый модуль `src/review/`, GitHub-клиент в `src/mcp/github.rs`, discovery/chunking в `src/rag/`, тесты и документация.
- Добавляется `.github/workflows/ai-review.yml` с изолированными `tests` и `review` jobs: первый не получает secrets и использует read-only permissions, второй исполняет только код base-ветки и получает `contents: read`, `pull-requests: write`.
- В GitHub Actions используются repository secret `OPENAI_API_KEY`, variables `FOX_REVIEW_PROVIDER`, `FOX_REVIEW_MODEL`, `FOX_REVIEW_EMBEDDING_MODEL` и необязательные variables лимитов; `GITHUB_TOKEN` предоставляется GitHub.
- Форматы существующих конфигураций, интерактивный CLI, MCP-инструменты и обычный Markdown-режим индексации остаются обратно совместимыми.
