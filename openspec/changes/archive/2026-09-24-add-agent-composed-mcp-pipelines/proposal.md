## Why

`fox-llm` умеет выполнять отдельные структурированные MCP-вызовы, но не имеет безопасного способа поручить агенту построить многошаговый план, передать результаты между шагами и выполнить всю цепочку как одну операцию. Для Дня 19 нужен воспроизводимый автоматический пайплайн из нескольких реальных MCP-инструментов, первым практическим сценарием которого станет отчёт по открытому GitHub-репозиторию.

## What Changes

- Добавить декларативный `PipelinePlan`, который агент формирует как JSON: последовательность шагов, аргументы и ссылки `$ref` на результаты предыдущих шагов.
- Добавить клиентский валидатор и исполнитель пайплайна, который разрешает только включённые MCP-инструменты, проверяет ссылки и схемы аргументов, ограничивает ресурсы и fail-closed останавливает цепочку при ошибке.
- Сохранить существующие проверки глобальных инвариантов и подтверждение каждого изменяющего состояние шага по его фактическим подставленным аргументам.
- Возвращать агенту структурированный trace с результатом каждого шага, не сохраняя технические сообщения пайплайна в истории диалога.
- Добавить в локальный MCP-сервер атомарные инструменты для сбора публичной статистики GitHub, расчёта производных метрик и формирования Markdown, а также общий инструмент `save_report_to_file` для сохранения произвольного текстового отчёта в файл.
- Добавить составной сценарий GitHub-отчёта, в котором агент выбирает доступные этапы и формирует план, а клиент выполняет настоящие последовательные MCP `tools/call`.
- Разделить лимит обычных модельных tool calls и внутренний лимит шагов валидированного пайплайна: не более трёх top-level вызовов модели и не более восьми шагов одного пайплайна.

## Capabilities

### New Capabilities

- `mcp-pipeline-execution`: декларативное планирование агентом, валидация, подстановка результатов, безопасное последовательное выполнение, сохранение произвольного текстового отчёта и трассировка многошаговых MCP-пайплайнов.
- `github-project-reporting`: получение публичных метрик GitHub-репозитория атомарными MCP-инструментами и создание Markdown-отчёта через агентский пайплайн.

### Modified Capabilities

- `mcp-tool-execution`: уточнить лимиты и гарантии для top-level tool calls и внутренних шагов пайплайна, сохранив allowlist, подтверждения, инварианты и правила истории.

## Impact

- `src/agent.rs`: распознавание декларативного плана, orchestration и передача итогового trace модели.
- `src/mcp/tools.rs`: provider-neutral типы плана, шагов, ссылок, trace и ошибок валидации.
- `src/mcp/mod.rs`: исполнение нескольких разрешённых `tools/call` через существующую MCP-сессию.
- `src/mcp/server.rs` и новые файлы только внутри `src/mcp/`: атомарные GitHub-инструменты, общий `save_report_to_file` и их бизнес-логика.
- `src/app.rs`: предварительный просмотр и подтверждение изменяющих шагов.
- `src/tests.rs`: регрессии порядка вызовов, передачи данных, allowlist, лимитов, ошибок, подтверждений и изоляции истории.
- Внешняя система: публичный GitHub REST API; первая версия не требует токена, не читает private-репозитории, traffic или security endpoints и не добавляет новый секрет в конфигурацию.
- Сохраняется обратная совместимость существующих одиночных MCP-вызовов и конфигурации.
