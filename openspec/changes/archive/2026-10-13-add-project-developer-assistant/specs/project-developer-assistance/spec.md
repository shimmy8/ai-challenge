## Purpose

Предоставить разработчику встроенную проектную справку, которая отвечает по актуальной документации и проверяемому состоянию локального репозитория.

## ADDED Requirements

### Requirement: Help сохраняет справку по командам и объявляет проектные вопросы
Система SHALL сохранять `/help` без аргументов как команду вывода доступных CLI-команд. После списка система SHALL отдельной строкой сообщать, что вопрос о проекте можно задать через `/help <вопрос>`.

#### Scenario: Обычная справка
- **WHEN** пользователь вводит `/help` без аргументов
- **THEN** система печатает существующий список команд и отдельную строку с синтаксисом `/help <вопрос>` без обращения к RAG, MCP или chat-provider

### Requirement: Help отвечает на вопросы по проектному контексту
Команда `/help <вопрос>` SHALL выполнять проектный retrieval независимо от состояния `/rag on|off`, создавать изолированного субагента, предоставлять ему доступ к автоматически запущенному help-only workspace MCP и формировать внутренне grounded-ответ с чистым пользовательским выводом. Вопрос SHALL передаваться и сохраняться без служебного префикса `/help`.

#### Scenario: Вопрос о структуре проекта
- **WHEN** пользователь вводит `/help как устроен MCP?`, совместимый индекс подготовлен и внутренний help-only MCP доступен
- **THEN** система использует релевантные проектные документы, текущую Git-ветку и результат CodeGraph, внутренне проверяет происхождение ответа и показывает пользователю только содержательный текст

#### Scenario: Глобальный RAG выключен
- **WHEN** пользователь выключил обычный RAG через `/rag off` и затем вводит `/help <вопрос>`
- **THEN** проектный retrieval всё равно выполняется

#### Scenario: Вопрос сохраняется без префикса команды
- **WHEN** `/help <вопрос>` успешно завершает ответ
- **THEN** история диалога содержит текст вопроса и итоговый ответ, но не содержит `/help` и технические MCP-вызовы как сообщения диалога

### Requirement: Каждый проектный вопрос выполняется изолированным субагентом
Система SHALL создавать новый временный субагент для каждого `/help <вопрос>`. Субагент MUST NOT получать историю, summary, профиль, активную задачу, долговременную память или MCP registry основного агента. Query rewrite MUST использовать только текущий очищенный вопрос, а generation SHALL получать только этот вопрос, разрешённые проектные RAG-фрагменты и результаты инструментов внутреннего help-only MCP.

#### Scenario: Последовательные независимые вопросы
- **WHEN** пользователь задаёт два разных `/help <вопрос>` последовательно
- **THEN** retrieval и ответ на второй вопрос не используют текст, тему, источники или состояние первого вопроса, кроме документации и текущего состояния workspace, заново найденных для второго вопроса

#### Scenario: Состояние основного агента заполнено
- **WHEN** основной агент имеет историю, summary, профиль, активную задачу или долговременные факты и пользователь вводит `/help <вопрос>`
- **THEN** эти данные не передаются help-субагенту и не влияют на query rewrite, tool calls или grounded generation

#### Scenario: Субагент использует специализированный MCP
- **WHEN** help-субагенту для ответа нужны сведения о Git или коде
- **THEN** он может напрямую вызвать `git_current_branch` или `codegraph_explore`, но не видит `save_report` и остальные MCP tools основного агента

#### Scenario: Временное состояние уничтожается
- **WHEN** help-субагент завершил ответ или получил ошибку
- **THEN** система уничтожает его историю и tool state, а в основной истории сохраняет только очищенный вопрос и успешно сформированный итоговый ответ

### Requirement: Проектный RAG использует только актуальную документацию
Для `/help <вопрос>` система SHALL допускать RAG-фрагменты только из корневого `README.md` и `openspec/specs/**/*.md`. Система MUST исключать `reports/**`, `openspec/changes/**`, локальные env-файлы, embedding credentials и любые иные источники даже при наличии их чанков в общем индексе.

#### Scenario: Индекс содержит документацию и отчёты
- **WHEN** общий индекс содержит чанки из `README.md`, `openspec/specs/`, `reports/` и `openspec/changes/archive/`
- **THEN** проектный retrieval возвращает только чанки из `README.md` и `openspec/specs/`

#### Scenario: В проектном корпусе нет релевантного документа
- **WHEN** разрешённые документы не проходят порог релевантности, но CodeGraph возвращает полезный контекст
- **THEN** система может сформировать grounded-ответ только по именованному CodeGraph-источнику

### Requirement: Документация и MCP-результаты образуют проверяемый контекст
Система SHALL преобразовывать успешные результаты прямых вызовов субагентом `git_current_branch` и `codegraph_explore` в отдельные именованные контекстные источники и передавать их вместе с RAG-фрагментами внутреннему механизму grounded-ответа. Внутренняя атрибуция MUST ссылаться только на фактически полученные источники, а содержательный ответ MUST NOT представлять предположение модели как факт проекта.

#### Scenario: Использованы все источники
- **WHEN** retrieval и оба MCP-инструмента возвращают контекст, использованный в ответе
- **THEN** внутренняя атрибуция различает документальные источники, Git-ветку и CodeGraph-контекст до формирования чистого пользовательского ответа

#### Scenario: Один источник недоступен
- **WHEN** один MCP-инструмент завершается ошибкой, но остаётся хотя бы один релевантный документ или успешный MCP-источник
- **THEN** система продолжает ответ по доступным источникам и явно сообщает об ограничении контекста

#### Scenario: Контекст полностью отсутствует
- **WHEN** разрешённые документы не дали релевантных фрагментов и оба MCP-источника недоступны или пусты
- **THEN** система не вызывает модель для содержательного ответа и сообщает, что контекст проекта получить не удалось

### Requirement: Пользовательский ответ скрывает служебную атрибуцию
После успешной внутренней grounding-проверки система SHALL показывать и сохранять только содержательный текст ответа help-субагента. Пользовательский вывод MUST NOT содержать разделы `Источники` или `Цитаты`, provenance metadata, `chunk_id`, `mcp://` URI, дословные evidence quotes либо tool trace. Система MAY показать короткое предупреждение, если часть ожидаемого контекста была недоступна.

#### Scenario: Успешный ответ использует документацию и MCP
- **WHEN** help-субагент сформировал и внутренне подтвердил ответ по RAG-чанкам и результатам MCP
- **THEN** пользователь видит только содержательный ответ без списка источников, цитат и технических идентификаторов

#### Scenario: Внутренние MCP-вызовы не засоряют интерактивный вывод
- **WHEN** help-субагент вызывает `git_current_branch` или `codegraph_explore`
- **THEN** события `mcp_server_call_start` и `mcp_server_call_finish` для help-only MCP не печатаются в пользовательский stdout

#### Scenario: Текст ответа переносится по границам слов
- **WHEN** строка ответа help-субагента длиннее доступной ширины терминала
- **THEN** отображаемый текст переносится между словами без изменения сохранённого ответа и без переформатирования fenced code blocks

#### Scenario: Чистый ответ сохраняется в основной истории
- **WHEN** успешный ответ help-субагента добавляется в историю основного агента
- **THEN** сохранённое сообщение совпадает с чистым пользовательским текстом и не содержит внутренний evidence envelope или tool trace

#### Scenario: Содержательное упоминание источников не считается утечкой
- **WHEN** проверенный ответ использует слово «источники» в обычном предложении, но не содержит отдельного служебного раздела атрибуции
- **THEN** система сохраняет содержательный ответ, удаляет только отдельные секции источников и нейтрализует технические идентификаторы без отказа всего `/help`-запроса

#### Scenario: Контекст доступен частично
- **WHEN** один из ожидаемых источников недоступен, но оставшегося контекста достаточно для ответа
- **THEN** система может показать краткое предупреждение об ограничении, не раскрывая список источников, цитаты или служебные MCP-данные

### Requirement: Проектный help ограничивает и изолирует MCP-сбор
Система MUST применять отдельный тайм-аут и предел размера к каждому проектному MCP-результату. Сбой, превышение лимита или недоступность CodeGraph MUST NOT повреждать историю, индекс или состояние обычного RAG.

#### Scenario: CodeGraph превышает тайм-аут
- **WHEN** `codegraph_explore` не завершается в установленный срок
- **THEN** его результат отмечается недоступным, остальные источники продолжают обрабатываться, а дочерний процесс не остаётся работать в фоне

#### Scenario: CodeGraph возвращает чрезмерный вывод
- **WHEN** результат CodeGraph превышает установленный предел
- **THEN** система безопасно ограничивает или отклоняет его, сообщает о причине и не передаёт модели неограниченный текст
