## Why

`fox-llm` умеет индексировать Markdown и вызывать MCP-инструменты, но не предоставляет единого сценария для вопросов разработчика о текущем проекте. Команда `/help` должна объединить актуальную проектную документацию, фактическую структуру кода и состояние Git, сохранив существующую справку по CLI.

## What Changes

- Сохранить `/help` без аргументов как список CLI-команд и добавить отдельную заметную строку о синтаксисе `/help <вопрос>`.
- Добавить `/help <вопрос>` для внутренне grounded-ответов о проекте независимо от состояния `/rag on|off`, возвращая пользователю чистый текст без разделов источников и цитат.
- Включить `README.md` в стандартный индекс и ограничивать проектный retrieval источниками `README.md` и `openspec/specs/**/*.md`; отчёты и архивные OpenSpec changes не использовать в ответах `/help`.
- Расширить локальный `workspace` MCP read-only инструментами текущей Git-ветки и CodeGraph-анализа проекта.
- Автоматически запускать вместе с интерактивным приложением внутренний help-only workspace MCP, который предоставляет только инструменты текущей Git-ветки и CodeGraph и не требует ручной регистрации.
- Создавать для каждого `/help <вопрос>` нового изолированного субагента без истории и памяти основного диалога; передавать ему только очищенный вопрос, релевантные RAG-фрагменты и прямой доступ к help-only MCP.
- Формировать внутренне проверяемый ответ из RAG-фрагментов и результатов MCP, но не показывать пользователю provenance metadata, `chunk_id`, MCP URI, источники, цитаты или tool trace.
- Документировать подготовку индекса, автоматический запуск help-only MCP и примеры использования ассистента разработчика.

## Capabilities

### New Capabilities

- `project-developer-assistance`: Поведение `/help <вопрос>`, изолированный субагент, объединение проектного RAG с Git и CodeGraph через MCP, внутренняя проверка grounding, чистый пользовательский вывод и деградация при недоступности источников.

### Modified Capabilities

- `document-indexing`: Стандартный Markdown-корпус дополнительно включает корневой `README.md`, а retrieval может быть ограничен разрешёнными проектными источниками.
- `mcp-tool-management`: Локальный `workspace` MCP объявляет read-only инструменты текущей Git-ветки и CodeGraph-анализа, а интерактивное приложение автоматически поднимает их help-only вариант с отдельным lifecycle.

## Impact

- Затрагиваются разбор интерактивных команд и вывод справки в `src/app.rs` и `src/cli.rs`.
- RAG discovery/retrieval получает дополнительный стандартный источник и фильтр источников; формат существующего SQLite-индекса менять не требуется.
- В `src/mcp/` добавляются workspace-инструменты, безопасный запуск дочерних процессов, тайм-ауты и ограничение вывода.
- Интерактивный runtime получает внутренний loopback MCP на случайном свободном порту и управляет его запуском и остановкой; пользовательская MCP-конфигурация не меняется.
- Project-help generation выполняется временным агентом с отдельным состоянием и ограниченным набором MCP tools.
- Для CodeGraph требуется установленный бинарник и актуальная `.codegraph/`; их отсутствие обрабатывается как недоступный дополнительный источник.
- Потребуются регрессионные тесты CLI, фильтрации retrieval, MCP-инструментов, fallback-поведения, grounded-синтеза и отсутствия служебной атрибуции в пользовательском выводе.
