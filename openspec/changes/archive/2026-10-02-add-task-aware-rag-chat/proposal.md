## Why

Интерактивный CLI уже сохраняет историю, выполняет RAG с проверяемыми источниками и передаёт активную задачу как рабочую память, но retrieval каждого хода опирается только на текущую реплику. Из-за этого короткие продолжения вроде «а какие у него ограничения?» могут потерять предмет разговора ещё до генерации ответа, а существующие проверки не доказывают сохранение цели на длинном диалоге.

## What Changes

- Добавить контекстный retrieval для интерактивного RAG: query rewrite получает текущий вопрос, ограниченный фрагмент недавних пользовательских реплик и компактные данные активной задачи, не подменяя исходный вопрос в истории или generation prompt.
- Использовать название, исходное описание и накопленные факты активной задачи как явную память цели, уточнений, ограничений и зафиксированных терминов; не передавать в retrieval профиль, MCP-инструменты, результаты внешних действий или полную историю.
- Гарантировать человекочитаемый раздел `Источники` для каждого завершённого пользовательского RAG-хода: проверенные источники и цитаты для grounded-ответа либо явное отсутствие релевантных источников для `no_relevant_context`.
- Сохранить существующий изолированный `rag-eval` для single-turn сравнения и добавить воспроизводимую проверку двух многоходовых RAG-сценариев по 10–15 сообщений с ожиданиями по цели, памяти и источникам.
- Сохранить sanitized результаты и разбор проверки Дня 25 в `reports/day25/` без credentials, embedding vectors и полных служебных prompt.

## Capabilities

### New Capabilities

- `rag-chat-evaluation`: воспроизводимые длинные сценарии и проверяемые результаты многоходового RAG-чата с памятью задачи.

### Modified Capabilities

- `rag-query`: интерактивный query rewrite становится контекстным и каждый завершённый RAG-ход явно сообщает источники либо их отсутствие.
- `task-lifecycle`: компактное состояние активной задачи предоставляет retrieval цель, уточнения, ограничения и термины без смешивания с историей или инструкциями.

## Impact

- `src/app.rs`: сбор ограниченного retrieval-контекста, маршрутизация интерактивного RAG и сценарного прогона.
- `src/agent.rs` и `src/memory.rs`: безопасное представление недавнего диалога и активной задачи для retrieval без загрязнения сохраняемой истории.
- `src/rag/`: контракт query rewrite, многоходовый evaluation runner и sanitized отчёт.
- `src/cli.rs`, `src/tests.rs`, `README.md`: параметры сценарного прогона, регрессионные проверки и документация.
- `reports/day25/`: два сценария, машинно-читаемый результат и итоговый отчёт.
- Формат SQLite и существующие записи задач остаются совместимыми; новые внешние зависимости не требуются.
