## Why

`fox-llm` умеет исследовать проект через CodeGraph и выполнять внешние MCP-вызовы, но основной интерактивный сценарий не позволяет поставить цель уровня «найди использования API» или «обнови документацию» и получить реальные, безопасно подтверждённые операции над файлами. День 34 должен превратить проектную помощь из текстовой справки в воспроизводимого файлового ассистента, не открывая модели произвольный доступ к файловой системе или shell.

## What Changes

- Добавить команду `/project <цель>`, которая запускает свежего изолированного субагента для работы только с текущим workspace и требует от него самостоятельно исследовать файлы перед итоговым ответом.
- Автоматически поднимать для этого запроса внутренний project-only MCP с ограниченными инструментами поиска, чтения, создания/замены файла и получения итогового diff.
- Ограничить все файловые операции каноническим корнем workspace, обычными UTF-8 файлами, лимитами входа/выхода и явным denylist секретов, локальных данных и служебных каталогов; запретить произвольные команды, удаление и выход через symlink.
- Для существующего файла применять optimistic concurrency по SHA-256 прочитанной версии, а для нового файла не допускать неявную замену уже существующей цели.
- Показывать перед каждой записью нормализованный путь и unified diff, выполнять ровно подтверждённое изменение и возвращать модели структурированный результат с признаком `changed`.
- Добавить автоматизированные сценарии поиска использования API и обновления документации во временном workspace минимум из трёх файлов, включая повторный запуск без дополнительного изменения.
- Описать ручную демонстрацию, ограничения и команды проверки в `reports/day34/README.md` на этапе реализации.

## Capabilities

### New Capabilities

- `project-file-assistance`: цель-ориентированная команда `/project`, изолированный файловый субагент, безопасный поиск/чтение/запись, итоговый diff и воспроизводимые сценарии Day 34.

### Modified Capabilities

- `mcp-tool-management`: интерактивное приложение автоматически предоставляет отдельный внутренний project-only MCP и управляет его жизненным циклом независимо от пользовательского MCP registry и help-only runtime.
- `mcp-tool-execution`: подтверждение файловой записи получает validated preview в форме unified diff и защищает выполнение от изменения файла между чтением и записью.

## Impact

- `src/app.rs` и `src/cli.rs`: разбор `/project`, запуск изолированного workflow, русскоязычный вывод прогресса и подтверждения.
- `src/agent.rs`: переиспользование существующего provider-neutral tool loop свежим project-субагентом без истории, профиля, памяти и активной задачи.
- `src/mcp/`: новый project-only runtime и файловые инструменты; весь серверный, lifecycle- и filesystem-код остаётся внутри MCP-модуля.
- `src/tests.rs` и локальные `#[cfg(test)]`-модули: scripted tool-calling, временные workspace, path/symlink/secret/limit/hash проверки и повторяемость.
- `Cargo.toml`: возможно добавление небольших библиотек для gitignore-aware обхода и детерминированного unified diff; точный выбор фиксируется в design.
- Пользовательский MCP registry и существующая команда `/help <вопрос>` сохраняют текущее поведение; изменение не является breaking.
