## MODIFIED Requirements

### Requirement: Enabled MCP tools are available to every supported provider
Система SHALL передавать OpenAI, Claude и Ollama актуальные определения автоматически включённых инструментов всех доступных зарегистрированных серверов под квалифицированными именами `server_id__tool_name`. Инструменты из denylist и инструменты недоступных серверов MUST быть скрыты; при наличии хотя бы одного инструмента система SHALL также передавать встроенное определение планирования pipeline. Инструменты MUST NOT передаваться запросам сжатия, суммаризации или проверки инвариантов.

#### Scenario: Tools from several servers are advertised
- **WHEN** два зарегистрированных сервера доступны и объявляют включённые инструменты
- **THEN** основной запрос содержит квалифицированные определения обоих серверов с исходными описаниями, схемами и аннотациями

#### Scenario: Enabled tool is advertised
- **WHEN** доступный сервер объявляет инструмент, отсутствующий в его denylist
- **THEN** основной запрос содержит его квалифицированное имя, описание, схему и аннотации

#### Scenario: Disabled tool is hidden
- **WHEN** нативное имя инструмента присутствует в denylist его сервера
- **THEN** квалифицированное определение не передаётся модели и прямой либо pipeline-вызов запрещён

#### Scenario: Unavailable server is isolated
- **WHEN** один зарегистрированный сервер не подключается, а другой доступен
- **THEN** основной запрос получает инструменты доступного сервера и безопасное предупреждение, но приложение продолжает работу

#### Scenario: Pipeline planner is advertised
- **WHEN** основной запрос получает хотя бы один доступный MCP-инструмент
- **THEN** он также получает встроенное структурированное определение планирования pipeline

#### Scenario: Auxiliary request does not receive tools
- **WHEN** агент выполняет суммаризацию, сжатие контекста или проверку инвариантов
- **THEN** запрос не содержит MCP-инструментов независимо от реестра

#### Scenario: Ollama is the selected provider
- **WHEN** основной запрос выполняется локальной Ollama-моделью и зарегистрированы доступные MCP-инструменты
- **THEN** Ollama получает те же разрешённые квалифицированные определения и встроенный planner, что и облачные провайдеры

### Requirement: Structured tool calls are executed and returned to the model
Система SHALL распознавать нативный структурированный tool call выбранного провайдера, выполнять соответствующий MCP `tools/call` и передавать фактический результат обратно тому же провайдеру для формирования итогового ответа. Текст, лишь похожий на запрос инструмента, MUST NOT запускать MCP-вызов.

#### Scenario: Tool result is used in final answer
- **WHEN** модель возвращает корректный structured tool call разрешённого инструмента, а MCP-сервер успешно его выполняет
- **THEN** система отправляет результат инструмента модели и показывает пользователю сформированный после этого итоговый ответ

#### Scenario: Plain text cannot invoke a tool
- **WHEN** ответ модели содержит имя инструмента или JSON-подобный текст без нативного structured tool call
- **THEN** система рассматривает его как обычный текст и не выполняет MCP-вызов

#### Scenario: Provider can finish without a tool
- **WHEN** модель возвращает итоговый текст без tool call
- **THEN** система завершает обычный цикл ответа без обращения к MCP `tools/call`

#### Scenario: Ollama requests a tool and completes locally
- **WHEN** Ollama возвращает корректный structured tool call и получает фактический результат разрешённого инструмента
- **THEN** продолжение запроса отправляется той же локальной модели, а итоговый текст проходит обычные проверки перед сохранением
