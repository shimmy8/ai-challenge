## Context

См. `proposal.md` для мотивации. Сейчас `fox-llm` является одним Rust binary: `main.rs` остаётся тонкой точкой входа, `app.rs` управляет интерактивным циклом, `cli.rs` содержит команды и `dialoguer`-меню, а `config.rs` загружает и атомарно по смыслу перезаписывает локальный `.fox-llm.json` с правами `0600`. Аргументы запуска пока ограничены `--dump-metrics`.

MCP добавляет новый сетевой протокол, асинхронный lifecycle и второй режим работы процесса. Интеграция должна оставаться необязательной: обычный запуск, провайдеры и старые конфигурации не зависят от доступности MCP-сервера.

## Goals / Non-Goals

**Goals:**

- Изолировать протокол MCP и демонстрационный сервер в ответственном модуле, сохранив `main.rs` тонким.
- Ограничить ожидание недоступного сервера и возвращать пользователя в интерактивное меню без завершения приложения.
- Хранить только устойчивые пользовательские настройки; список доступных инструментов каждый раз получать с сервера.
- Сделать сетевую часть тестируемой на временном loopback-порту без внешних сервисов.

**Non-Goals:**

- Передавать MCP-схемы OpenAI или Claude, обрабатывать model tool calls либо автоматически выполнять инструменты.
- Поддерживать несколько серверов, OAuth, пользовательские заголовки, stdio-серверы, resources, prompts или динамические уведомления `tools/list_changed`.
- Держать MCP-соединение постоянно открытым между выполнениями `/mcp`.

## Decisions

### Использовать официальный Rust SDK и Streamable HTTP

Клиент и сервер используют `rmcp` с необходимыми feature-флагами Streamable HTTP. Это даёт стандартные handshake и `tools/list`, не воспроизводя JSON-RPC вручную. Streamable HTTP выбран вместо stdio, потому что сервер должен запускаться независимо, а пользователь настраивает адрес уже работающего процесса. Legacy HTTP+SSE не используется.

Альтернативы: stdio потребовал бы, чтобы клиент запускал дочерний процесс; ручной JSON-RPC уменьшил бы число MCP-зависимостей, но переложил бы совместимость протокола на проект.

### Сохранить один binary с двумя режимами запуска

`cargo run` продолжает запускать интерактивный клиент, `cargo run -- --dump-metrics` сохраняет текущее поведение, а `cargo run -- --mcp-server` запускает демонстрационный сервер. Разбор аргументов возвращает явный режим приложения и отклоняет несовместимые или неизвестные комбинации. Серверный режим делегируется MCP-модулю; `main.rs` только выбирает режим.

Альтернатива — второй binary target — сделала бы обычный `cargo run` неоднозначным и потребовала бы дополнительной структуры только ради демонстрации.

### Представить MCP-конфигурацию типом с безопасным значением по умолчанию

В `Config` добавляется поле с `#[serde(default)]`, содержащее `server_url: Option<String>` и `enabled_tools: Vec<String>`. Отсутствующая секция десериализуется как ненастроенный сервер. Имена включённых инструментов нормализуются как уникальный стабильный список.

Адрес нового сервера сначала разбирается как абсолютный `http` или `https` URL, затем проходит handshake и `tools/list`. Только успешная проверка заменяет адрес. При смене адреса выбор инструментов очищается, потому что одинаковые имена на разных серверах не означают одинаковых возможностей.

Альтернатива — хранить весь последний ответ `tools/list` — создаёт устаревающий кэш и дублирует источник истины сервера.

### Создавать короткоживущее соединение для каждого входа в меню

Обработчик `/mcp` подключается к текущему endpoint, получает список инструментов и использует его на протяжении одного сеанса меню. Выход из меню корректно закрывает клиент. Handshake и получение списка ограничиваются таймаутом; сетевые и протокольные ошибки преобразуются в краткие русские сообщения.

Долгоживущее соединение пока не приносит пользы: агент не вызывает инструменты и не подписывается на изменения. При будущей реализации tool calling lifecycle можно будет поднять на уровень `AgentPool` без изменения формата конфигурации.

### Разделить сетевую логику и интерактивное представление

Новый `mcp.rs` содержит типы конфигурации/описания инструментов, подключение, получение списка, сервер `echo` и чистые операции согласования включённых имён. `cli.rs` отвечает за `Select`, `MultiSelect`, ввод URL и форматирование; `app.rs` оркестрирует меню и сохранение `Config`.

Для смены адреса и выбора инструментов применяется commit-on-confirm: отмена или ошибка не меняют объект конфигурации и файл. Сохранение выбранных инструментов принимает только имена из последнего успешного `tools/list`, поэтому исчезнувшие записи очищаются при подтверждении.

### Демонстрационный сервер слушает только loopback

Сервер использует фиксированный документированный endpoint `http://127.0.0.1:8000/mcp`, объявляет один детерминированный инструмент `echo(text)` и пишет состояние запуска в stderr/терминал, не смешивая логи с протокольными ответами. Loopback исключает случайное открытие учебного сервера во внешнюю сеть; аутентификация для него не требуется.

Внутренняя функция запуска принимает уже связанный listener либо адрес, что позволяет тесту использовать `127.0.0.1:0` и избежать конфликтов портов.

## Risks / Trade-offs

- [Добавление `rmcp` и HTTP server stack увеличит время сборки и размер dependency tree] -> включить только нужные feature-флаги и не добавлять OAuth или прочие MCP-возможности.
- [Недоступный endpoint может задержать интерактивный CLI] -> ограничить handshake и `tools/list` коротким таймаутом и позволить отменить повторную настройку.
- [Список инструментов может измениться после открытия меню] -> считать ответ `tools/list` снимком текущего сеанса; следующий `/mcp` загрузит его заново.
- [Сохранённые имена могут устареть] -> отображать только пересечение с актуальным списком и очищать устаревшие имена при подтверждённом сохранении.
- [Инструмент отмечен как включённый, но пока не вызывается агентом] -> явно описать границу Дня 16 в меню и документации; состояние является allowlist для следующего этапа.
- [Фиксированный порт 8000 может быть занят] -> завершать сервер с понятной ошибкой; тесты всегда используют автоматически выбранный порт.

## Migration Plan

1. Добавить MCP-конфигурацию с serde-default и проверить загрузку файлов текущего и legacy-форматов.
2. Добавить клиент, меню и серверный режим без изменения поведения обычного запуска.
3. Обновить документацию и выполнить автоматические проверки.
4. Для отката удалить MCP-команду, модуль и зависимости. Старые версии на текущем serde-пути игнорируют неизвестную секцию `mcp`, поэтому ручная миграция локального файла не требуется; пользовательские диалоги и SQLite не затрагиваются.
