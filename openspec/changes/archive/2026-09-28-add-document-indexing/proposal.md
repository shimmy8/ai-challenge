## Why

`fox-llm` умеет работать с диалоговым контекстом и долговременной памятью, но не имеет воспроизводимого способа подготовить локальные документы для последующего RAG-поиска. Для дня 21 нужен отдельный пайплайн, который индексирует достаточно большой реальный корпус, сохраняет embeddings вместе с происхождением чанков и позволяет предметно сравнить две стратегии chunking.

## What Changes

- Добавить неинтерактивный CLI-режим индексации Markdown-корпуса из `reports/**/*.md` и актуальных `openspec/specs/**/*.md` с возможностью явно передать другие локальные источники.
- Реализовать стратегии `fixed` и `structural`: фиксированный размер с overlap и разбиение Markdown по заголовкам с ограничением размера слишком больших разделов.
- Ввести provider-neutral интерфейс embeddings и единственную отдельную конфигурацию `.fox-embeddings.json`, не связанную с chat-провайдерами агента и не переопределяемую CLI-параметром. Файл хранит provider, endpoint, модель, размерность, batch size и credentials по аналогии с `.fox-llm.json`; первая реализация использует OpenAI-compatible endpoint, по умолчанию OpenAI `text-embedding-3-small`, и допускает переключение на совместимый локальный endpoint без изменения агентского flow.
- Сохранять документы, чанки, embeddings и метаданные `source`, `title`, `section`, `chunk_id`, стратегию и модель в отдельном локальном SQLite-индексе `.fox-index.db`.
- Не отправлять повторно неизменившиеся тексты: переиспользовать embedding по хешу содержимого, модели и размерности.
- Формировать сравнение стратегий по количеству и размерам чанков, заполненности секций, токенам embedding API и времени выполнения; сохранять JSON по явному `--comparison-output` в дополнение к записи запуска в SQLite.
- Добавить отчёт дня 21 с описанием корпуса, параметров, результатов сравнения и командами воспроизведения.
- Добавить безопасный коммитируемый `fox-embeddings.example.json`; локальный `.fox-embeddings.json` с credentials SHALL иметь права `0600`, быть исключён из Git и получить в `AGENTS.md` такой же запрет на чтение, индексирование, анализ, цитирование и вывод, как локальные env-файлы с секретами.
- Не добавлять на этом этапе retrieval, генерацию RAG-ответа, PDF-парсинг, FAISS или встроенный runtime локальной embedding-модели; локальная модель подключается как отдельный совместимый сервис.

## Capabilities

### New Capabilities

- `document-indexing`: Обнаружение локальных Markdown-документов, две стратегии chunking, независимо настраиваемый embedding provider, сохранение локального SQLite-индекса с метаданными и экспорт сравнения результатов.

### Modified Capabilities

Нет.

## Impact

- Появится новый модуль `src/rag/`; `src/main.rs` останется только точкой объявления модулей и запуска приложения.
- Изменятся только разбор startup-режима и верхнеуровневый запуск приложения; `Agent`, chat-provider configuration, диалоговый режим и MCP-серверы сохранят прежнее поведение.
- Появятся отдельные `EmbeddingConfig` и provider factory внутри `src/rag/`; `.fox-llm.json` не будет источником endpoint, модели, размерности или credentials для embeddings.
- Будут добавлены локальный `.fox-embeddings.json` и безопасный `fox-embeddings.example.json`; `.gitignore` исключит локальный файл, а `AGENTS.md` разрешит для документации и разработки использовать только example без значений credentials.
- Будет добавлена отдельная SQLite-база `.fox-index.db`, которую необходимо исключить из Git вместе с WAL/SHM-файлами.
- HTTP-интеграция будет ограничена OpenAI-compatible embedding adapter и изолирована за интерфейсом, допускающим локальный endpoint и детерминированную тестовую реализацию без сети и расходов.
- Тесты покроют отдельную конфигурацию, выбор провайдера, обнаружение корпуса, обе стратегии chunking, стабильные метаданные и идентификаторы, сериализацию векторов, повторное использование embeddings, ошибки API и сравнительные метрики на временной базе.
