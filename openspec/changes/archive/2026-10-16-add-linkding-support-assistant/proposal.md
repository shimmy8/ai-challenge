## Why

Дню 33 нужен воспроизводимый пользовательский сценарий поддержки, в котором ассистент отвечает по документации реального продукта и одновременно учитывает состояние конкретного обращения. Отдельный HTTP-режим с веб-интерфейсом позволит запустить учебный стенд одной командой, создать тикет и сразу продолжить диалог с grounded-ответами по документации linkding.

## What Changes

- Добавить отдельный режим запуска support-сервиса, который на одном loopback-адресе обслуживает JSON API и простой веб-интерфейс создания тикета и общения с ассистентом.
- Добавить отдельную SQLite-базу поддержки для пользователей, тикетов и сообщений, не связанную с хранилищем CLI-сессий и памяти.
- Добавить support MCP-сервер с инструментами создания и чтения тикетов, чтения истории и добавления сообщений; все обращения HTTP-слоя к тикетной базе проходят через MCP.
- Создавать для каждого вопроса ограниченный снимок тикета и его переписки и передавать его модели как недоверенный пользовательский контекст.
- Добавить независимый RAG-индекс по локально зафиксированной документации и FAQ linkding, не смешивая его с общим проектным индексом `fox-llm`.
- Возвращать через API и веб-интерфейс проверенный ответ, цитаты из базы знаний и актуальную историю тикета; при недоступности тикета, RAG или модели завершать запрос явной безопасной ошибкой без негрунтованного ответа.
- Сохранить существующие интерактивный CLI, `.fox-sessions.db` и `.fox-index.db` без изменения поведения.

## Capabilities

### New Capabilities

- `support-web-application`: отдельный HTTP-режим, JSON API и встроенный веб-интерфейс для создания тикета и продолжения диалога.
- `support-ticket-management`: отдельное SQLite-хранилище поддержки и MCP-контракт для пользователей, тикетов и сообщений.
- `linkding-support-rag`: независимая база знаний linkding, retrieval и grounded-генерация с учётом снимка тикета.

### Modified Capabilities

- Нет.

## Impact

- `src/app.rs` и разбор startup mode получат новую ветку запуска support-сервиса.
- Новый HTTP runtime и статические ресурсы веб-интерфейса будут отделены от интерактивного CLI.
- Весь MCP-код тикетной системы, включая сервер, типы и работу с базой, будет расположен в `src/mcp/` и экспортирован через `src/mcp/mod.rs`.
- RAG-модули будут переиспользованы с явно заданным отдельным путём индекса и отдельным discovery-корнем документации linkding.
- Потребуются новые HTTP-, MCP-, SQLite- и RAG-регрессионные тесты, фикстуры документации linkding и отчёт `reports/day33/`.
- Новых внешних сервисов и обязательной CRM нет; учебный стенд работает на локальных HTTP, MCP и SQLite-компонентах, используя уже настроенные generation- и embedding-провайдеры.
