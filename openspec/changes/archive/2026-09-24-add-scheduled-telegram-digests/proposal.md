## Why

Сейчас `fox-llm` выполняет MCP-действия только во время интерактивного запроса и не может самостоятельно подготовить и доставить результат по расписанию. Для задания Дня 18 нужен постоянно работающий контур, который переживает закрытие CLI, собирает календарные данные, формирует сводку и отправляет её пользователю в Telegram.

## What Changes

- Добавить сохраняемые в SQLite одноразовые и ежедневные фоновые задания с восстановлением после перезапуска MCP-сервера и журналом запусков.
- Добавить MCP-инструменты для создания, просмотра, приостановки, возобновления, удаления и немедленного запуска календарной сводки.
- Научить CalDAV-клиент читать события выбранного Яндекс Календаря за заданный абсолютный интервал.
- Добавить ограниченный фоновый генератор сводки через настроенного OpenAI или Claude без истории диалога и без доступа к MCP-инструментам.
- Добавить доставку сводки в один заранее настроенный Telegram-чат и сохранять результат каждой попытки доставки.
- Добавить детерминированную сводку без LLM как резервный результат, чтобы сбой провайдера не приводил к потере уведомления.
- Расширить локальную конфигурацию MCP-сервера настройками Telegram без сохранения токена, chat ID или ключей провайдера в заданиях, результатах и логах.
- Документировать запуск MCP-сервера как долгоживущего процесса и ограничения гарантии доставки.

## Capabilities

### New Capabilities

- `scheduled-background-jobs`: Сохраняемое расписание, единственный фоновый worker, восстановление запусков и MCP-управление заданиями.
- `telegram-digest-delivery`: Безопасная генерация календарной сводки и её доставка в заранее настроенный Telegram-чат с журналом результата и резервным текстом.

### Modified Capabilities

- `yandex-calendar-events`: CalDAV-интеграция дополнительно читает события выбранного календаря за заданный интервал для фоновой сводки.

## Impact

- `src/mcp/server.rs`: общий для MCP-сессий scheduler runtime и новые MCP-инструменты управления.
- `src/mcp/calendar.rs`: CalDAV `REPORT`, разбор возвращённых iCalendar-событий и безопасные ошибки чтения.
- Новые модули планировщика, генератора сводки и Telegram-клиента; миграции SQLite для заданий и запусков.
- `src/providers.rs`, `src/config.rs` и запуск `--mcp-server`: ограниченный фоновый вызов выбранного провайдера и загрузка необходимых настроек.
- `.env-mcp.example`, README и `reports/day18/`: безопасная конфигурация Telegram и инструкция эксплуатации.
- `src/tests.rs`: регрессии расписания, восстановления, изоляции секретов, CalDAV-чтения, fallback и доставки.
- Существующие интерактивные команды и формат сессий остаются совместимыми; новые сторонние Rust-зависимости не обязательны для минимального расписания `once`/`daily`.
