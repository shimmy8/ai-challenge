## Purpose

Позволяет локальному MCP-серверу надёжно выполнять сохраняемые задания по времени без открытого интерактивного CLI и предоставлять агенту агрегированную историю запусков.

## ADDED Requirements

### Requirement: Scheduler tools expose a bounded job contract
MCP-сервер SHALL предоставлять инструменты создания, просмотра, приостановки, возобновления, удаления и немедленного запуска календарной сводки. Расписание SHALL поддерживать одноразовый абсолютный момент и ежедневное локальное время с явной временной зоной; если зона не передана, система SHALL использовать `Europe/Moscow`. Изменяющие состояние инструменты MUST быть объявлены не read-only, а просмотр расписаний и истории SHALL быть read-only.

#### Scenario: Daily schedule is created
- **WHEN** подтверждённый вызов задаёт ежедневную сводку в 08:00 и `Europe/Moscow`
- **THEN** сервер сохраняет активное задание, возвращает его идентификатор и ближайший абсолютный момент запуска

#### Scenario: One-time schedule is created
- **WHEN** подтверждённый вызов задаёт будущий абсолютный момент со смещением
- **THEN** сервер сохраняет одноразовое задание и возвращает нормализованный момент запуска

#### Scenario: Invalid schedule is rejected
- **WHEN** время, временная зона или одноразовый момент отсутствуют, противоречат типу расписания либо некорректны
- **THEN** сервер не сохраняет задание и возвращает понятную ошибку валидации

### Requirement: Jobs and runs survive process restarts
Система SHALL сохранять определения заданий, следующий момент запуска, состояние и журнал запусков в SQLite до подтверждения создания задания. После перезапуска MCP-сервера scheduler SHALL восстановить активные задания без необходимости подключать интерактивный CLI.

#### Scenario: Server restarts before a future run
- **WHEN** MCP-сервер перезапущен до `next_run_at` активного задания
- **THEN** задание восстанавливается и выполняется в сохранённый момент

#### Scenario: Daily run was missed while server was stopped
- **WHEN** ежедневное задание просрочено при запуске сервера
- **THEN** система выполняет не более одного компенсирующего запуска и назначает следующую будущую календарную дату без воспроизведения каждого пропущенного дня

#### Scenario: One-time run was missed while server was stopped
- **WHEN** невыполненное одноразовое задание уже просрочено при запуске сервера
- **THEN** система выполняет его один раз и после завершения не назначает повторный запуск

### Requirement: Each due occurrence is claimed at most once locally
Один процесс MCP-сервера SHALL иметь один общий scheduler для всех MCP-сессий. Он MUST атомарно зафиксировать запуск до внешних запросов и MUST NOT одновременно выполнять две копии одного задания. Завершение, ошибка или неопределённый исход SHALL оставлять проверяемую запись запуска.

#### Scenario: Several MCP clients are connected
- **WHEN** наступает срок задания при нескольких активных MCP-сессиях
- **THEN** общий scheduler создаёт ровно одну запись запуска и начинает одно выполнение

#### Scenario: Previous execution is still running
- **WHEN** наступает очередной срок задания, для которого уже есть незавершённый запуск
- **THEN** система не начинает параллельную копию и фиксирует пропуск либо перенос согласно сохранённому результату

#### Scenario: Process stops during a run
- **WHEN** сервер перезапускается с запуском в незавершённом состоянии
- **THEN** система помечает предыдущий запуск прерванным и не представляет его успешно доставленным

### Requirement: Job lifecycle is controllable and observable
Система SHALL позволять приостанавливать, возобновлять и удалять задания по идентификатору, а также запускать активное или приостановленное задание немедленно без изменения его очередного планового момента. История SHALL возвращать последние запуски, итог последнего запуска и агрегированные количества успешных, неуспешных, прерванных и неопределённых доставок.

#### Scenario: Job is paused
- **WHEN** пользователь подтверждает приостановку задания
- **THEN** новые плановые запуски не начинаются до подтверждённого возобновления

#### Scenario: Job is run manually
- **WHEN** пользователь подтверждает немедленный запуск существующего задания
- **THEN** система создаёт отдельный ручной запуск и сохраняет исходное `next_run_at`

#### Scenario: Agent requests aggregate history
- **WHEN** агент вызывает read-only инструмент истории для существующего задания
- **THEN** результат содержит безопасные данные задания, последние запуски, агрегированные счётчики и последнюю сохранённую сводку без секретов

### Requirement: Background execution has an explicit availability boundary
Плановые задания SHALL выполняться без работающего интерактивного CLI, пока процесс MCP-сервера запущен. Система MUST NOT заявлять о непрерывной работе за периоды, когда MCP-сервер не был запущен, и SHALL показывать пропущенные или компенсированные запуски в истории.

#### Scenario: CLI is closed while MCP server stays online
- **WHEN** срок активного задания наступает без подключённого MCP-клиента
- **THEN** scheduler выполняет задание и сохраняет результат независимо от CLI

#### Scenario: MCP server is offline
- **WHEN** срок задания проходит при остановленном MCP-сервере
- **THEN** доставка не происходит в этот момент, а после запуска применяется сохранённая политика восстановления
