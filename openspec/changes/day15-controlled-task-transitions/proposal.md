## Why

Сейчас `/task next` разрешает перейти к реализации с пустым планом и завершить задачу до выполнения проверок: подтверждение пользователя не проверяет готовность текущей фазы. День 15 требует, чтобы переход был допустим только после выполнения условий этапа, а реализация начиналась по утверждённой версии плана.

## What Changes

- Сохранять монотонную версию плана задачи и номер версии, утверждённой пользователем. Версия меняется при фактическом изменении фактов или пунктов TODO во время `planning`.
- При переходе `planning -> execution` показывать пользователю план и его версию; подтверждение атомарно утверждает именно эту версию и переводит задачу в `execution`. Если план изменился во время подтверждения, переход отклоняется.
- Разрешать `planning -> execution` только с непустыми списками выполнения и валидации, `execution -> validation` только после завершения всех пунктов выполнения, `validation -> done` только после завершения всех проверок. Проверять условия в хранилище, а не только в CLI.
- Сообщать причину недопустимого перехода, сохранять фазу без изменений и при продолжении сессии восстанавливать версию плана и его утверждение.
- Добавить регрессионные сценарии для преждевременных и устаревших переходов, поведения агента в каждой фазе, отмены подтверждения и продолжения после паузы.
- При открытии существующей базы добавить недостающие столбцы версии без переноса смысла прежних задач; для ручной проверки создать новую задачу в текущей базе.
- Подготовить отчёт Дня 15 с описанием реализации и воспроизводимым примером ручной проверки переходов. Наблюдения пользователя добавить после его прогона.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `task-lifecycle`: условия переходов, утверждение версии плана пользователем и восстановление этих данных вместе с задачей.

## Impact

- `src/memory.rs`: версия и утверждение плана в модели задачи, правила готовности фаз.
- `src/sessions.rs`: новая схема SQLite и атомарная проверка и запись перехода.
- `src/app.rs`, `src/cli.rs`: показ плана и версии перед подтверждением, понятные причины отказа.
- `src/agent.rs`: передача актуальной версии и статуса утверждения в рабочий контекст при необходимости.
- `src/tests.rs`: регрессионные тесты переходов, восстановления и создания новой задачи в существующей базе.
- `reports/day15/report.md`: описание и ручной сценарий с местом для последующих выводов.
- Внешние зависимости и сетевой API не меняются.
