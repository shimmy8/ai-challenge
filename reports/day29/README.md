# День 29. Оптимизация локальной LLM для суммаризации встреч

## Цель

Эксперимент оптимизирует установленную локальную `qwen3.5:4b` для преобразования
русскоязычного протокола встречи в один JSON-объект с кратким итогом, актуальными
решениями, задачами, открытыми вопросами и рисками. RAG, MCP, пользовательская
память, история сессии, облачные провайдеры и изменение квантования не
используются.

Во всех профилях используются одни и те же веса `qwen3.5:4b` с квантованием
`Q4_K_M`. Ollama aliases отличаются только `num_ctx` и `num_predict`, а runner
передаёт выбранную температуру и prompt.

## Данные и профили

- `dataset.json` содержит девять синтетических протоколов: по три `short`,
  `medium` и `long`. Повторяемые нейтральные блоки разворачиваются runner'ом
  детерминированно и не добавляют эталонных фактов.
- `profiles.json` фиксирует параметры сравнения.
- `profiles/Modelfile.*` создают лёгкие Ollama aliases поверх существующих
  blobs модели и не загружают новые веса.

| Профиль | Temperature | Context | Max output | Prompt |
| --- | ---: | ---: | ---: | --- |
| `baseline` | 1.0 | 4096 | 1024 | общий |
| `compact` | 0.0 | 4096 | 256 | специализированный |
| `balanced` | 0.2 | 8192 | 512 | специализированный |

## Подготовка Ollama aliases

```bash
ollama create fox-summary-baseline -f reports/day29/profiles/Modelfile.baseline
ollama create fox-summary-compact -f reports/day29/profiles/Modelfile.compact
ollama create fox-summary-balanced -f reports/day29/profiles/Modelfile.balanced
```

Команды используют только уже установленную публичную модель. `.env-mcp`,
`.fox-embeddings.json`, API keys и другие локальные credentials для эксперимента
не нужны и не читаются.

## Запуск

```bash
cargo run -- summarize-eval \
  --dataset reports/day29/dataset.json \
  --profiles reports/day29/profiles.json \
  --output reports/day29/results.json
```

Команда пишет progress-логи в stderr: start, preflight, безопасные ID текущего
сценария и профиля, cold/warm, elapsed, tokens, pass/fail, агрегирование и путь
готового отчёта. Текст протокола, сырой ответ, prompt и authorization data в лог
не выводятся.

`results.json` публикуется атомарно и содержит только синтетические входы,
ответы на них, проверки, параметры воспроизводимости и доступные metadata
Ollama. `size_vram` в этом отчёте означает память загруженной модели по данным
Ollama; это не полная RAM процесса, температура корпуса и не энергопотребление.

## Критерии

Кейс проходит только при одновременном выполнении всех проверок:

- ответ является одним JSON-объектом без Markdown;
- присутствуют все актуальные решения и задачи;
- владельцы и сроки совпадают с эталоном, отсутствующие значения равны `null`;
- отменённые и неподтверждённые сведения отсутствуют;
- нет неизвестных ID и придуманных сущностей;
- открытые вопросы и риски совпадают с эталоном;
- `summary` содержит не более пяти предложений.

Агрегаты считаются отдельно для каждого профиля и каждой категории длины.
Рекомендация выбирается среди `compact` и `balanced`: сначала по pass rate,
затем по медиане warm latency и loaded model memory.

## Очистка необязательных aliases

После завершения эксперимента aliases можно удалить; базовая модель останется:

```bash
ollama rm fox-summary-baseline
ollama rm fox-summary-compact
ollama rm fox-summary-balanced
```

## Результаты

Полный локальный прогон выполнен 8 октября 2026 года. Runner обработал все 27
запланированных комбинаций: девять сценариев по одному разу для каждого из
трёх профилей. Пропущенных или повторяющихся пар сценарий/профиль нет. Исходные
машинно-читаемые данные сохранены в `results.json`.

### Итоговое сравнение

| Профиль | Полностью пройдено | Валидный контракт | Median warm latency | К baseline | Input tokens | Output tokens | Median loaded memory |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `baseline` | 0/9 (0%) | 1/9 (11,1%) | 26,604 с | — | 10 085 | 2 058 | 3 181 547 355 B (2,96 GiB) |
| `compact` | 0/9 (0%) | 6/9 (66,7%) | 22,249 с | −16,4% | 10 655 | 1 728 | 3 181 547 355 B (2,96 GiB)¹ |
| `balanced` | 1/9 (11,1%) | 8/9 (88,9%) | 23,420 с | −12,0% | 23 749 | 1 951 | 3 335 792 884 B (3,11 GiB) |

`Валидный контракт` означает, что ответ удалось разобрать как единственный
JSON-объект требуемой схемы. Этого недостаточно для полного прохождения:
структурно валидный ответ также должен совпасть с эталоном по всем фактам.

¹ Для `compact` Ollama не вернула запись alias в `/api/ps` в шести из девяти
наблюдений; runner сохранил `null` и причину. Приведённая медиана вычислена по
трём доступным наблюдениям и потому не равна полному измерению всех запусков.

### Влияние длины входа

| Категория | Baseline warm median | Compact warm median | Balanced warm median | Полные проходы baseline/compact/balanced |
| --- | ---: | ---: | ---: | ---: |
| `short` | 16,662 с | 10,037 с (−39,8%) | 10,579 с (−36,5%) | 0 / 0 / 0 |
| `medium` | 20,576 с | 21,792 с (+5,9%) | 22,581 с (+9,7%) | 0 / 0 / 0 |
| `long` | 29,308 с | 32,225 с (+10,0%) | 70,837 с (+141,7%) | 0 / 0 / 1 |

У `balanced` длинный контекст позволил обработать значительно больше входных
токенов: 19 244 для трёх long-кейсов против 6 150 у каждого профиля с окном
4096. Цена — заметный рост времени на длинных протоколах и увеличение медианы
loaded model memory примерно на 4,8% относительно baseline. Медианная warm
скорость генерации, вычисленная из per-case значений, составила около 10,89,
10,66 и 10,25 output tokens/s для `baseline`, `compact` и `balanced`
соответственно.

### Качество и ошибки

- `baseline` с общим prompt и `temperature=1.0` прошёл JSON-контракт только в
  одном случае и не прошёл ни одного кейса полностью.
- Специализированный prompt значительно улучшил соблюдение формата:
  `compact` дал 6/9, а `balanced` — 8/9 структурно валидных ответов.
- Единственный полный успех — `long-mobile-scope` у `balanced`. Этот профиль
  корректно сохранил актуальное решение, задачу, открытый вопрос и риск из
  длинного протокола.
- В 12 из 27 ответов parser зафиксировал нарушение контракта: пять ответов не
  соответствовали требуемой JSON-схеме, ещё семь содержали не один JSON-объект
  или постороннее содержимое. Прогон при этом продолжился штатно.
- Оставшиеся 15 ответов разобрались, но 14 из них провалили хотя бы одну
  фактическую проверку. Наиболее частая проблема — несовпадение набора решений;
  также встречались лишние или пропущенные риски, вопросы и задачи.
- Все три long-ответа `compact` завершились на лимите 256 output tokens и были
  отклонены как содержащие не один JSON-объект. Это указывает на слишком жёсткий
  `num_predict` для данного формата, но причинность требует отдельного повторного
  эксперимента.

Сообщения `passed=false` в progress-логе являются результатами оценивания, а не
авариями команды. Команда завершила агрегацию и атомарно записала полный файл.

### Выбранный профиль

Runner рекомендовал `balanced`. По заданному правилу качество имеет приоритет
над задержкой и памятью: `balanced` — единственный оптимизированный профиль с
полностью пройденным кейсом и лучший по соблюдению JSON-контракта. По сравнению
с исходным `baseline` итоговая доля полных проходов выросла с 0% до 11,1%,
общая медиана warm latency снизилась на 12,0%, а медиана loaded model memory
выросла на 4,8%.

Результат нельзя считать готовой production-настройкой: восемь из девяти
сценариев `balanced` всё ещё не прошли все проверки. Практический вывод этого
эксперимента — использовать `balanced` как основу следующей итерации, затем
усилить контракт prompt/декодирования и повторить benchmark. Для коротких
входов `compact` быстрее, но текущий лимит ответа непригоден для длинных кейсов.

### Ограничения измерений

- Для каждой пары выполнен один запуск; доверительные интервалы и оценка
  вариативности отсутствуют.
- Cold/warm отражает только первый запрос каждого alias и последующие запросы,
  а не полностью контролируемую температуру устройства или состояние кэшей.
- `loaded_memory_bytes` получен из Ollama `/api/ps`; это не полная RAM процесса
  или системы. Для части запусков `compact` показатель недоступен.
- Температура компьютера и энергопотребление не измерялись.
- Профили используют одинаковые веса `qwen3.5:4b` и квантование `Q4_K_M`, поэтому
  эксперимент сравнивает prompt, temperature, context window и max tokens, но
  не квантование или размер модели.
