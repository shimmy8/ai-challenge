# День 33. Ассистент поддержки пользователей

Учебный сервис поддержки для linkding запускается как отдельный режим `fox-llm`.
Один процесс обслуживает встроенный браузерный UI и JSON API, а тикеты читает и
изменяет через отдельный внутренний MCP runtime. Продуктовые ответы строятся по
отдельному RAG-индексу документации linkding; общий проектный индекс не
используется.

## Архитектура

```text
браузер -> axum UI/API -> support orchestrator
                              |         |
                              |         +-> query rewrite -> linkding index
                              |                              -> grounded LLM
                              v
                    internal support MCP -> .fox-support.db
```

Создание тикета атомарно сохраняет пользователя, открытый тикет и описание как
первое сообщение. Перед каждым ответом оркестратор получает карточку и
ограниченный снимок истории через MCP. Тикет и история маркируются в prompt как
недоверенные данные; citations разрешены только для извлечённых Markdown-чанков.
Grounded generation не получает MCP tools. Успешный проверенный ответ сохраняется
через `add_ticket_message`; при ошибке исходный вопрос не теряется.

## Запуск демонстрации

Нужны обычная конфигурация выбранного chat-провайдера и локальная
`.fox-embeddings.json`. Содержимое этих файлов в отчёт не попадает.

```bash
cargo run -- index \
  --source reports/day33/knowledge-base \
  --strategy structural \
  --index-path .fox-linkding-index.db

cargo run -- support \
  --addr 127.0.0.1:8088 \
  --ticket-db .fox-support.db \
  --index-path .fox-linkding-index.db
```

Откройте `http://127.0.0.1:8088`, создайте тикет, например «REST API возвращает
401», и задайте уточнение «Где взять подходящий token?». Первый ответ появляется
сразу после создания. История остаётся на странице и в отдельной support DB.

Ожидаемый grounded-ответ объясняет, что REST API использует token пользователя
из Settings и заголовок `Authorization` со схемой `Token`, со ссылкой на раздел
`Авторизация и API token`. Для вопроса про пропавшие snapshots ответ должен
ссылаться на `Импорт, экспорт и резервные копии` или `Архивирование закладок и
снимки страниц`, а не на факты из карточки тикета.

## API и отказоустойчивость

- `POST /api/tickets` возвращает `201` после сохранения тикета даже при частичном
  AI-сбое; поле `error` описывает причину.
- `POST /api/tickets/{id}/messages` сначала сохраняет пользовательское сообщение.
  При последующем сбое error envelope содержит `ticket_id`, `message_id` и
  `message_saved: true`.
- malformed JSON, неизвестные поля, неверные длины и отсутствующий тикет не
  запускают модель и возвращают стабильный безопасный ответ.
- UI вставляет пользовательский и модельный текст через `textContent`, поэтому
  строка `<script>` отображается как текст.

## Корпус и provenance

Корпус находится в `reports/day33/knowledge-base/`. Это краткий русскоязычный
snapshot официальной документации linkding `v1.47.0` (`24b5ad6`) и собственный
FAQ. Upstream распространяется под MIT; URL и карта источников перечислены в
`knowledge-base/manifest.md`. В каталоге нет credentials, env-файлов,
пользовательских диалогов и сгенерированных данных.

## Ограничения

Сервис предназначен только для локальной демонстрации: нет аутентификации,
операторских ролей, вложений, SLA и публичного hosting. AI-ходы сериализованы
одним gate. История для модели ограничена, а полный helpdesk функционал вроде
назначения оператора или почтового канала не реализован.

## Проверка

Перед завершением изменения выполняются:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
```

Loopback integration-тесты требуют окружение, в котором разрешено открывать
локальные TCP-порты.

Фактический финальный прогон 15 октября 2026 года:

- `cargo fmt --all -- --check` — успешно;
- `cargo clippy --all-targets --all-features -- -D warnings` — успешно;
- `cargo test` — 282 passed, 0 failed.

Автоматизированный HTTP-сценарий работает с временной support DB и scripted
провайдером: создаёт тикет, возвращает первый ответ с citation, отправляет два
уточнения и проверяет порядок ролей. Live browser-прогон с настоящими chat- и
embedding-провайдерами остаётся ручным шагом, поскольку требует локальных
credentials, которые не читаются и не сохраняются при разработке.
