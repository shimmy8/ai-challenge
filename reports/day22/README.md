# День 22. Первый RAG-запрос

## Что реализовано

Интерактивный агент поддерживает два процессных режима:

- `/rag off` — прежний ответ LLM без локального retrieval;
- `/rag on` — embedding вопроса, exact cosine search по `structural`-чанкам,
  сборка top-5 контекста и ответ LLM с отображением фактически переданных
  источников;
- `/rag status` — текущее состояние без сетевых запросов.

RAG выключен при старте и не сохраняется в `.fox-llm.json`. Если индекс или
embedding-конфигурация отсутствуют либо несовместимы, запрос завершается ошибкой
до вызова chat provider и не переходит молча в обычный режим.

## Контрольный набор

Набор [`control-questions.json`](control-questions.json) содержит 10 вопросов по
корпусу `reports/` и `openspec/specs/`. Для каждого вопроса зафиксированы
человекочитаемое ожидание, обязательные строковые фрагменты и ожидаемые
относительные пути источников.

## Воспроизведение

Сначала нужен совместимый structural-индекс:

```bash
cargo run -- index --strategy structural
```

Сравнение выполняется явно и делает 20 chat-запросов и 10 запросов embedding:

```bash
cargo run -- rag-eval \
  --questions reports/day22/control-questions.json \
  --output reports/day22/comparison.json
```

Каждая пара использует одинаковые provider, model и настройки, но два новых
агента без истории, профиля, памяти, MCP и session writes. Результат сначала
собирается в памяти и публикуется атомарно только после полного успеха.

Для демонстрации команда построчно выводит в терминал текущий вопрос, полный
ответ агента без RAG, найденные RAG-источники, полный ответ агента с RAG и
метрики обоих режимов. Управляющие символы удаляются; тексты чанков, credentials,
vectors и embedding-конфигурация в progress-лог не выводятся.

## Разбор ошибок

Два провала связаны прежде всего с retrieval. Structural-индекс содержит много
коротких секций: cosine search нашёл правильный файл Дня 21 для обоих вопросов,
но для defaults ожидаемый OpenSpec-источник не вошёл в top-5, а для сравнения
стратегий в контекст попали соседние фрагменты без итоговой таблицы. Это
подтверждает наблюдение Дня 21 о необходимости объединять очень короткие
соседние секции либо добавлять reranking/hybrid search.

Строковая fact coverage — прозрачная, но грубая эвристика. Например, корректные
`8/8` не совпали с ожидаемым фрагментом «восем», а семантически верный ответ про
`unknown` потерял балл из-за другой формулировки. Поэтому агрегат используется
вместе с ручным разбором, а не как полноценная семантическая оценка.

Совместимость embedding space в этой версии проверяется по model и dimensions.
Одинаковые значения у разных endpoint теоретически не гарантируют одинаковое
пространство; fingerprint provider/endpoint остаётся улучшением следующей версии.

`comparison.json` может содержать вопросы, ответы и безопасные metadata
источников, но не содержит API keys, Authorization headers, vectors,
content hashes или полную embedding-конфигурацию.
