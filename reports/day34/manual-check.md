# Архитектура файлового ассистента

Файловый ассистент реализован как изолированный `/project`-субагент. `run_project_file_subagent` наследует модель и инварианты родительского агента, отключает pipeline-инструмент, ограничивает число tool-вызовов и подключает защищённый `ProjectWorkflowExecutor`.

MCP-сервер `ProjectWorkspaceServer` предоставляет шесть операций: стабильный список файлов, literal-поиск, чтение UTF-8 с SHA-256, создание/замену файла, ограниченный Git diff и исследование связей через CodeGraph. Основная файловая логика сосредоточена в `ProjectWorkspace`, а проверка путей — в `ProjectWorkspacePolicy`.

Безопасность строится на относительных канонизированных путях внутри workspace, запрете symlink и чувствительных путей, лимитах размера/вывода и optimistic concurrency. Замена разрешена только после полного чтения той же версии и проверки `expected_sha256`; создание — после точного `list_files`, подтвердившего отсутствие цели. Запись выполняется через временный файл с синхронизацией и атомарной публикацией.

Workflow-обёртка контролирует порядок исследования: для вопросов о символах сначала нужен CodeGraph, затем чтение исходников; поиск служит fallback. Она собирает evidence и trace, отклоняет необоснованные записи, нормализует policy-denial и формирует итог с проверенными/изменёнными путями и unified diff.
