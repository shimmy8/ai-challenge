# День 19. Композиция MCP-инструментов

## Результат

`fox-llm` поддерживает автоматические линейные пайплайны из нескольких MCP-инструментов. Агент сам формирует декларативный план и вызывает встроенный клиентский инструмент `fox_execute_pipeline`; клиент валидирует план, последовательно выполняет реальные MCP `tools/call`, передаёт JSON-результаты между шагами и возвращает агенту единый trace.

Первый прикладной сценарий создаёт отчёт по публичному GitHub-репозиторию:

```text
github_repository_metadata
  -> github_project_activity
  -> calculate_github_metrics
  -> render_github_report
  -> save_report_to_file
```

Оркестратор находится на стороне агента, а не MCP-сервера. Поэтому атомарные инструменты можно вызывать отдельно и комбинировать в другие цепочки. План содержит от одного до восьми шагов; ссылка вида `{"$ref":"metadata.output"}` передаёт полный JSON-результат ранее выполненного шага.

Перед выполнением клиент проверяет allowlist, уникальность id, направление ссылок и JSON Schema фактических аргументов. Для каждого шага отдельно применяются глобальные инварианты. Изменяющие состояние инструменты, включая `save_report_to_file`, требуют подтверждения уже после подстановки аргументов. Ошибка, отказ или таймаут останавливают цепочку, а оставшиеся шаги получают статус `skipped`.

## Доступные GitHub-метрики

Инструменты работают с публичным GitHub REST API без токена и возвращают:

- исходные данные: описание, даты создания и последнего push, stars, forks, subscribers, open issues/PR, default branch и распределение языков с долями;
- активность за период 1–365 дней: commits, active contributors, issues, pull requests, Actions runs и releases;
- производные показатели: доля закрытых issues, доля merged PR, медианное время merge, CI success rate и средний интервал между releases;
- исходные счётчики issues, pull requests, Actions runs и releases рядом с производными метриками;
- секцию `Data coverage` с отдельным статусом каждого источника, явные `unavailable` и warnings, если источник недоступен или выборка была усечена.

Расчёт метрик и Markdown-рендеринг детерминированы и не требуют дополнительного LLM-вызова. `save_report_to_file` не зависит от GitHub: он принимает произвольное UTF-8 содержимое и безопасное имя одного файла в рабочем каталоге MCP-сервера. Существующий файл не заменяется без `overwrite: true`; пути и symbolic links отклоняются.

## Настройка и запуск

1. Запустить локальный сервер:

   ```bash
   cargo run -- --mcp-server
   ```

   Для крупных репозиториев рекомендуется предварительно добавить в локальный
   `.env-mcp` необязательный токен без write-разрешений:

   ```dotenv
   GITHUB_TOKEN="github_pat_..."
   ```

   Он используется только MCP-сервером как чувствительный Bearer header и не
   попадает в модель, trace, логи или ошибки.

2. В другом запуске клиента открыть `/mcp`, указать `http://127.0.0.1:8000/mcp` и включить пять инструментов из схемы выше.
3. Попросить агента сформировать отчёт, например:

   ```text
   Собери статистику публичного репозитория rust-lang/rust за последние 30 дней,
   подготовь Markdown-отчёт и сохрани его в rust-report.md.
   ```

Агент может выбрать прямой одиночный вызов или сам сформировать `fox_execute_pipeline`. Для полного сценария ожидается trace примерно такой формы:

```json
{
  "name": "github-project-report",
  "status": "succeeded",
  "steps": [
    {"id": "metadata", "tool": "github_repository_metadata", "status": "succeeded"},
    {"id": "activity", "tool": "github_project_activity", "status": "succeeded"},
    {"id": "metrics", "tool": "calculate_github_metrics", "status": "succeeded"},
    {"id": "report", "tool": "render_github_report", "status": "succeeded"},
    {"id": "save", "tool": "save_report_to_file", "status": "succeeded", "state_changed": true}
  ]
}
```

Технический план, промежуточные вызовы и trace не сохраняются в истории диалога; там остаются исходный запрос пользователя и финальный ответ агента.

## Ограничения

- GitHub API без аутентификации имеет низкий rate limit; для публичных отчётов поддерживается необязательный `GITHUB_TOKEN`, но private repositories по-прежнему не входят в сценарий.
- Traffic, security endpoints, GraphQL, ветвления, циклы, параллельные шаги и rollback не входят в эту версию.
- GitHub statistics может временно отвечать `202`; инструмент выполняет ограниченные повторы с паузами 1, 2 и 4 секунды. Для contributors после этого используется fallback по уникальным авторам коммитов периода, а недоступная метрика помечается warning.
- Сбор `github_project_activity` ограничен 120 секундами, чтобы крупные репозитории успевали пройти backoff и ограниченную пагинацию; остальные MCP-инструменты сохраняют стандартный 15-секундный тайм-аут.
- Пагинация продолжается до временной границы отчёта, но ограничена 20 страницами на источник и общим бюджетом HTTP-запросов. Усечённый источник отдельно отмечается в `Data coverage` и warning.
- Файл создаётся в рабочем каталоге процесса MCP-сервера; перенос в `reports/day19/` или другое место выполняется отдельно.

## Проверка

Реализация проверяется следующими командами:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
```

End-to-end тест запускает локальные mock GitHub API и MCP server, после подтверждения выполняет все пять настоящих MCP-вызовов и проверяет созданный отчёт.
