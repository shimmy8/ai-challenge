# fox-llm

Интерактивный CLI-клиент на Rust для общения с OpenAI и Claude.

Запросы обрабатывает отдельная сущность `Agent`: она хранит историю диалога,
формирует запрос к выбранному LLM API и сохраняет успешный ответ. Интерфейс
работает с агентом через `AgentPool`. Сейчас пул содержит одного агента, но уже
запускает свои экземпляры как независимые асинхронные задачи, поэтому может быть
расширен до параллельной работы без изменения логики агента.

Режим ответа и температура копируются в настройки агента. При смене провайдера,
модели, режима или температуры пул обновляет настройки и очищает историю.

## Запуск

```bash
cargo run
```

Чтобы после каждого успешного ответа сохранять метрики в JSON Lines-файл
`fox-metrics.log`, запустите приложение с флагом:

```bash
cargo run -- --dump-metrics
```

Каждая строка лога содержит время записи, ID сессии, имя активной ветки,
провайдера, модель, номер агента, длительность запроса и входные/выходные токены
запроса и текущей сессии.

При первом запуске CLI предложит выбрать провайдера, а затем способ добавления
ключа: открыть официальную страницу для создания нового или ввести уже
существующий. Каждый введённый символ ключа отображается звёздочкой, поэтому
длина ввода видна, но сам ключ остаётся скрытым. Настройки сохраняются в
`.fox-llm.json` в текущей директории. Файл исключён из Git и на Unix получает
права `0600`.

Режимы ответа хранятся отдельно в `fox-modes.json`. В нём нет секретов, поэтому
его можно коммитить в репозиторий и использовать всей командой.

## Команды

- `/provider` — сменить провайдера;
- `/model` — загрузить доступные модели текущего провайдера и выбрать модель;
- `/mode` — выбрать режим ответа или создать новый;
- `/temperature` — изменить температуру ответов;
- `/compression` — выбрать стратегию управления контекстом и размер окна;
- `/profile` — создать, выбрать, посмотреть или отключить профиль персонализации;
- `/task` — создать или продолжить задачу, изменить TODO или подтвердить следующий этап;
- `/remember <текст>` — сохранить факт в долговременную память;
- `/forget <id>` — удалить долговременный факт после подтверждения;
- `/memory` — показать содержимое трёх слоёв памяти;
- `/new` — очистить историю и начать новую сессию;
- `/sessions` — выбрать сохранённую сессию и продолжить диалог;
- `/quit` — выйти;
- `/help` — показать подсказку.

Начните ввод с `/`: CLI покажет продолжение команды. Нажмите `Tab`, чтобы
подставить команду или увидеть все подходящие варианты. Невведённая часть
подсказки отображается приглушённым цветом; `Enter` сразу выполняет показанную
команду.

Под активной строкой ввода закреплён статус-бар с текущими провайдером, моделью,
режимом, температурой, стратегией контекста и размером окна (для branching —
именем активной ветки). Перед выводом результата строка
статуса очищается,
поэтому повторяющиеся статусы не попадают в историю прокрутки терминала.

Во время запроса CLI показывает состояние агента, а после завершения — его номер,
ответ, время выполнения и две группы токенов: входные и выходные для последнего
API-вызова, а также накопительные входные и выходные за текущую сессию. Значения
последнего вызова берутся из поля `usage` ответа API и добавляются к итогу только
после успешного ответа. `/new` и смена настроек обнуляют накопительный итог.

## Режимы ответа

Команда `/mode` открывает список сохранённых режимов. В нём всегда доступен
режим «Без ограничений» и пункт создания нового режима. Пользовательский режим
содержит название и инструкции. Формат, длина и условие завершения ответа
задаются непосредственно в тексте этих инструкций.

Инструкции вводятся в многострочном режиме: вставьте промпт целиком, затем
введите `/done` на отдельной строке. Если режим с таким названием уже есть, CLI
предложит заменить его.

Режимы сохраняются в `fox-modes.json`, а последний выбранный режим — в локальном
`.fox-llm.json`. При смене режима история диалога очищается, чтобы новые
инструкции не смешивались с предыдущей сессией.

Команда `/temperature` задаёт степень вариативности ответов. Для OpenAI доступен
диапазон от `0` до `2`, для Claude — от `0` до `1`. Для моделей GPT-5.1 и новее
CLI отправляет `reasoning.effort: "none"`, чтобы разрешить управление
температурой. Более ранние reasoning-модели, включая `gpt-5-mini`, поддерживают
только значение по умолчанию `1`; CLI сообщит об этом вместо изменения настройки.
У каждого провайдера сохраняется собственное значение, которое отображается при
запуске рядом с текущим режимом. При его изменении начинается новая сессия.

Команда `/model` получает доступные для API-ключа модели напрямую у текущего
провайдера. Начните печатать часть названия модели, чтобы отфильтровать список,
затем выберите вариант стрелками и нажмите `Enter`. Для OpenAI из списка
исключаются модели других API: генерации
изображений, аудио, транскрипции, realtime, embeddings и модерации, а также
legacy-модели, несовместимые с Responses API. Выбранная
модель сохраняется отдельно для каждого провайдера в `.fox-llm.json`; после её
смены начинается новая сессия. Нажмите `Esc`, чтобы закрыть список без изменения
модели.

Провайдеры хранятся списком. Модели и ключи можно изменить в `.fox-llm.json`:

```json
{
  "last_provider": "openai",
  "last_mode": "Краткий ответ",
  "providers": [
    {
      "provider": "openai",
      "api_key": "sk-...",
      "model": "gpt-5.6-luna",
      "temperature": 1.5
    },
    {
      "provider": "claude",
      "api_key": "sk-ant-...",
      "model": "claude-sonnet-5",
      "temperature": 0.7
    }
  ]
}
```

Формат `fox-modes.json`:

```json
{
  "modes": [
    {
      "name": "Краткий ответ",
      "instructions": "Ответь тремя пунктами. Используй не более 1000 символов."
    }
  ]
}
```

Старый формат конфигурации автоматически преобразуется при запуске.

API-ключи являются секретами. Не коммитьте и не отправляйте этот файл другим людям.

## Сохранение контекста

После каждого успешного ответа диалог автоматически сохраняется в локальной
SQLite-базе `.fox-sessions.db`. История внутри записи хранится в компактном
формате TOON. Файл базы исключён из Git.

Команда `/sessions` показывает сохранённые диалоги, отсортированные по времени
последнего сообщения. Выбранную сессию можно продолжить или удалить после
подтверждения. При продолжении восстанавливаются её провайдер, модель,
температура, режим ответа, стратегия сжатия, размер окна, отдельно сохранённое
summary, sticky facts, все ветки branching и checkpoint. Последние сообщения
восстанавливаются с исходными ролями и текстом. Команда
`/new` начинает отдельную сессию, не удаляя прежние диалоги.


## Стратегии управления контекстом (день 10)

Команда `/summary` удалена. `/compression` открывает переключатель из четырёх
стратегий. Для воспроизводимых сценариев доступны и короткие формы:

- `/compression summary 10` — прежняя LLM-сводка и последние N сообщений;
- `/compression sliding 10` — строго последние N сообщений без LLM-сжатия;
- `/compression facts 10` — JSON-блок key-value facts и последние N сообщений;
- `/compression branching` — независимые ветки диалога от checkpoint.

Допустимый размер окна — от 1 до 1000 сообщений. В режиме summary значение 0
оставляет полную историю и отключает сжатие командой /compression summary 0.
Настройка по умолчанию сохраняется в `.fox-llm.json`, а стратегия и окно
каждой созданной сессии — в таблице `session_context`. Изменение
`/compression` сразу обновляет активную сессию. Старое поле
`summary_messages` автоматически читается как размер окна, поэтому существующая
конфигурация мигрирует без ручного редактирования.

В режиме **summary** старая часть истории объединяется с предыдущей сводкой
отдельным запросом к модели. Сводка ограничена 4000 символами и добавляется к
инструкциям как данные контекста.

В режиме **sliding-window** агент отправляет модели только N самых новых
сообщений, включая текущий запрос. Отдельного запроса к модели и производных
данных нет.

В режиме **sticky-facts** перед каждым основным запросом агент обновляет через
модель отдельный JSON-объект с актуальными целями, ограничениями,
предпочтениями, решениями и договорённостями. В основной запрос попадают facts и
последние N сообщений. Facts сохраняются в `session_context` SQLite и
восстанавливаются вместе с сессией.

Для **branching** сначала сохраните общую точку и создайте минимум две ветки:

```text
/compression branching
/checkpoint
Предложи вариант с PostgreSQL
/load
Предложи вариант с SQLite
/switch Предложи вариант с PostgreSQL
```

`/checkpoint` сохраняет общую точку. Первое обычное сообщение после него
автоматически создаёт ветку, а её имя формируется из текста этого сообщения.
`/load` возвращает диалог к checkpoint и показывает последний ответ модели,
который был получен до его создания; следующее обычное сообщение начинает
новую ветку. `/switch` открывает интерактивный список веток,
`/switch <имя>` позволяет быстро переключиться вручную, а `/branches`
показывает их список; текущая ветка отмечается звёздочкой.

Команды `/checkpoint`, `/load`, `/switch` и `/branches` появляются в подсказках
и работают только при выбранной стратегии branching. Все ветки сохраняются в
`session_branches`, checkpoint — в `session_checkpoints`, а состояние ожидания
новой ветки — в `session_context`. История, summary и facts хранятся отдельно
для каждой ветки. После перезапуска `/sessions` восстанавливает активную ветку
или загруженный checkpoint. Создание checkpoint, загрузка checkpoint и
переключение синхронизируются с SQLite сразу, без ожидания следующего ответа
модели.

Во всех стратегиях полный исходный архив активной истории хранится отдельно от
рабочего контекста. Это позволяет безопасно менять стратегию и размер окна.
Служебные запросы summary и sticky-facts учитываются в накопительных токенах
сессии; метрики отдельного ответа относятся к основному запросу.

## Модель памяти агента (день 11)

Память агента разделена на три слоя с разным жизненным циклом:

- **краткосрочная** — сообщения, summary, sticky facts и ветки текущей сессии;
- **рабочая** — название, текущая фаза и краткий TODO выбранной задачи;
- **долговременная** — именованный профиль с пользовательскими инструкциями.

Обычные сообщения никогда автоматически не становятся профилем или TODO.
Содержимое памяти меняется только явными действиями в `/profile` и `/task`, а
`/memory` показывает все три слоя, использованные для следующего запроса.

### Профили

Команда `/profile` открывает интерактивное меню создания, выбора, просмотра и
отключения профиля. Также доступны формы `/profile show`, `/profile new`,
`/profile use <id|имя>` и `/profile off`. Инструкции выбранного профиля
добавляются к системному prompt после инструкций режима ответа и применяются
независимо от стратегии сжатия.

Профили хранятся в таблице `profiles`, а использовавшая профиль сессия содержит
его `profile_id`. Если профиль меняется после появления сообщений, текущая
сессия остаётся сохранённой и начинается новая.

### Задачи

Команда `/task` позволяет создать или продолжить задачу, посмотреть состояние,
заменить TODO и перейти к следующей фазе. Для воспроизводимых сценариев доступны:

```text
/task show
/task new
/task use <id|имя>
/task todo Проверить миграцию и тесты
/task next
/task off
```

Новая задача начинается в `planning` и проходит только последовательные этапы:

```text
planning -> execution -> validation -> done
```

Агент может предложить `/task next`, но не меняет фазу самостоятельно. Команда
показывает исходную и целевую фазы, а запись в БД выполняется только после
подтверждения пользователя. TODO также заменяется только после подтверждения.
Задачи хранятся отдельно от сессий, поэтому одну задачу можно продолжить в новом
диалоге. Сессия, использовавшая задачу, сохраняет её `task_id`.

При активной задаче над обычным статус-баром отображается отдельная строка
`Этап задачи: <phase>`: `planning` выделен синим, `execution` — жёлтым,
`validation` — пурпурным, `done` — зелёным. Без активной задачи эта строка не
показывается.

Выбор другого профиля или другой задачи в непустом диалоге автоматически
начинает новую сессию, сохраняя прежнюю. `/new` очищает активную память сессии;
профили и задачи остаются в SQLite и доступны для повторного выбора.

Имена профилей ограничены 80 символами, инструкции профиля и TODO — 2000
символами, а названия задач — 120 символами.

## Долговременные факты и персонализация (день 12)

Новый инкремент не меняет сессии и задачи Дня 11. Команда
`/remember <текст>` сохраняет только отдельный долговременный факт:

```text
/remember Пользователь пишет примеры на Rust
/remember Проект использует SQLite
```

Факты хранятся в таблице `memory_entries`, доступны после `/new` и при
продолжении старой сессии и добавляются к каждому основному запросу как данные,
а не как инструкции. Обычные сообщения, summary, sticky facts, профиль, TODO и
фаза задачи не переносятся в эту таблицу автоматически.

`/forget <id>` показывает выбранный факт и удаляет его только после
подтверждения. `/memory` выводит идентификаторы всех фактов, чтобы нужную запись
можно было удалить явно.

Профиль теперь обозначается в интерфейсе как профиль персонализации. При
`/profile new` CLI отдельно запрашивает:

- стиль ответа;
- формат ответа;
- ограничения.

Каждое поле вводится одной строкой и подтверждается обычным `Enter`, после чего
поля собираются в единый текст инструкций. Профили, сохранённые раньше в
свободном формате, продолжают загружаться без преобразования. Активный профиль
передаётся в `instructions` OpenAI или `system` Claude при каждом запросе и не
зависит от выбранной стратегии сжатия контекста.
